# 設計: Service Worker ログレベル統一

## 方針

- `background.js` は既存の `bgLogError` / `bgLogWarn` / `bgLogInfo` / `bgLogDebug` を利用する。
- `monitoringConfigManager.js` は既存の `mcmLogger` に統一し、ロガー未初期化時だけ同ファサードのフォールバックを使用する。
- 生の `console.*` を機械的に同一レベルへ置換せず、イベントの性質で分類する。
- アラームのクリア・予約・有効化確認は反復する設定詳細として DEBUG にする。実際の監視開始・終了・検知は INFO のままとする。
- 自動判定のシナリオ1/2/4/8は、削除済みの `6710` ではなく有効な商品ページを使う。出現・初回未検知はテスト専用キーワード、消失は在庫表示を使い、事前の商品在庫状態に依存しない。
- popup のログレベル復元は `getLogLevel` の `success: true` 契約で判定し、HTML の既定値で保存済み値を上書き表示しない。
- Service Worker のログレベル復元直後は、実効モードを確認する起動診断ログを1回だけ直接出力する。ERROR 設定時にも確認可能とし、通常のレベル判定対象外として文書化する。

## レベル分類

| 区分 | レベル | 例 |
| --- | --- | --- |
| 詳細・反復状態 | DEBUG | Storage 読込、移行済み確認、整合性補正の詳細、アラーム設定 |
| 運用イベント | INFO | 監視開始・終了、検知、保存完了、外部通知成功 |
| 継続可能な異常 | WARN | 旧形式の設定、補正・フォールバック |
| 処理不能な失敗 | ERROR | Storage/API/設定処理の例外 |

## 対象外

- 共有ログライブラリをロードする前の起動ログは、ログレベル設定を復元できないため対象外とする。
- `chrome.scripting.executeScript` が対象ページへ注入する関数内の `console.*`、popup/content script のログは、Service Worker のログレベル設定が届かないため対象外とする。

## 検証

- unit test を全件実行する。
- `plan/todo.md` の整合性チェックと JavaScript 構文確認を実行する。
- Chrome で INFO 時に設定読込・アラーム設定の詳細が出ず、検知・通知・警告・エラーが出ることを手動確認する。
