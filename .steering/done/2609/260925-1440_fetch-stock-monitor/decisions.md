## 🧩 Decision一覧

### D-001: 設定オーバーライド方式の採用

- **決定内容**:
  - `scheduled-watch-sites.json` を直接編集せず、`chrome.storage.local` でオーバーライド設定を管理する

- **背景**:
  - scheduled-watch-sites.json は Chrome拡張の静的ファイルであり、実行時に直接更新できない
  - popupからサイトごとの取得方式を変更する導線が必要

- **検討した選択肢**:
  - 案A: JSONファイル直接編集（Node.jsスクリプト等で）
  - 案B: chrome.storage.local でオーバーライド
  - 案C: 別の設定ファイルを作成

- **採用理由**:
  - 案Bは拡張機能内で動的に更新可能
  - 既存のstorage管理パターンと整合する
  - ユーザーがpopupから設定変更できる

- **却下理由**:
  - 案A: 静的ファイルは実行時更新不可
  - 案C: 設定ファイルが分散し管理が複雑化

- **影響範囲**:
  - background.js の設定読み込みロジック
  - popup.js の取得方式選択UI

- **関連ドキュメント**:
  - requirements.md: 制約事項
  - design.md: データ構造変更

- **ステータス**:
  - [x] 確定
  - [ ] 見直し予定
  - [ ] 廃止

- **備考**:
  - マージ順序: 基本設定 → オーバーライド の順で上書き

### D-002: A系高頻度Fetchは監視タブのContent Scriptで実行する

- **決定内容**:
  - 単一URL・複数URLの高頻度Fetchは、監視中タブに注入済みのContent Scriptから同一URLを取得する。

- **背景**:
  - 利用者は5〜20秒の高頻度を維持しつつ、タブをリロードしないFetch方式を選択した。
  - MV3 Service Workerの短周期タイマーだけに依存すると、休止・再起動の影響を受けやすい。

- **採用理由**:
  - 既存の高頻度セッションと同じタブ・タイマーを使え、監視間隔を維持できる。
  - 同一オリジンのFetchとしてCookieを含むページ取得ができる。

- **影響範囲**:
  - content.js の高頻度セッション、background.js の評価・フォールバック処理

- **ステータス**:
  - [x] 確定
