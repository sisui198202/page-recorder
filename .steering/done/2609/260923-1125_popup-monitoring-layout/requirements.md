# requirements.md

## 目的

単一URL監視と複数URL監視の操作導線を、popup上で短く分かりやすく配置する。

## 背景

- 単一URL監視の開始・停止・即座取得は監視対象より後ろにあり、操作の起点が分かれやすい。
- 複数URL監視の全体制御はEC監視サイトより後ろにあり、一覧を操作する導線から離れている。
- 複数URL監視の状態サマリーは、少ない状態情報に対してカードの余白と装飾が大きい。
- 単一URLの「即座取得」は指定URL選択中もアクティブタブを取得するため、`chrome://` ページが選ばれるとHTML取得に失敗する。
- 起点: `plan/docs/popup-監視レイアウト改善.md` と、2026-09-23のユーザー依頼。

## 即座取得の受け入れ条件

- 「アクティブタブ」選択時は、現在のアクティブタブのスクリーンショットとDOMのouterHTMLを保存する。
- 「指定URL」選択時は、入力済み指定URLのスクリーンショットとDOMのouterHTMLを保存する。
- 即座取得の役割が、監視を開始せずに対象ページのスクリーンショットとDOMのouterHTMLを一回保存する機能であることをpopupに明記する。
