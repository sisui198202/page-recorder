# ログ重複抑止の分類定義

## 目的

複数URL監視を含むbackgroundのログで、異なる監視セッションの終端・結果ログが重複抑止により欠落しないようにする。同時に、周期的な進捗ログの過剰表示は制御できる状態にする。

## 背景

現行の `shouldSuppressLog(message, level)` は、WARN / ERROR以外をメッセージ文字列だけで5秒間抑止している。`🛑 系統Aセッション停止完了` のように同じ文言で異なるsessionIdを持つ終端ログも抑止され、手動検証で実際の停止状態と表示ログが一致しない。

## ユーザーストーリー

- EC監視の運用者として、複数URLが同時に検知・停止したとき、各セッションの停止結果をService Workerログから確認したい。
- 開発者として、周期的な待機・状態照会ログは必要以上に反復表示されず、重要な結果ログだけを確実に追跡したい。

## 機能要件

- ログを、終端・結果、操作・設定、周期進捗、調査詳細に分類する。
- 終端・結果ログは、同じ文言でも重複抑止しない。
- 周期進捗・調査詳細を抑止する場合は、イベント種別と対象コンテキスト（sessionId、tabId、siteId等）を区別できるキーを使う。
- WARN / ERRORは現行どおり常に出力する。
- 分類と抑止対象を、コード・単体テスト・ログ表記ガイドで一致させる。

## 受け入れ条件

- [ ] 異なるsessionIdの `🛑 系統Aセッション停止完了` が5秒以内でも各1件出力される。
- [ ] 同一対象・同一イベントの周期進捗ログだけが、定義済みの時間内に抑止される。
- [ ] WARN / ERRORの出力挙動を変更しない。
- [ ] 重複抑止の分類・キー・対象外イベントがログ表記ガイドに記録される。
- [ ] 自動テストとAの2 URL同時検知の手動確認で確認できる。

## スコープ外

- `monitoringConfigManager.js` に残る生 `console.*` の統一。
- ログの色分け、絵文字、全ログ文言の一括整理。
- popup / content scriptのログ基盤変更。

## 制約・影響範囲

- MV3 Service Workerのbackgroundログ基盤を対象にし、既存のログレベル設定を維持する。
- 主な変更候補は `src/background/background.js`、`tests/unit/background-functions.test.js`、`.claude/rules/logging.md`、`docs/ログ表記ガイド.md`。
- 先行タスクである複数URL監視の情報設計改善は、本タスク完了後に手動受け入れ確認を再開する。
