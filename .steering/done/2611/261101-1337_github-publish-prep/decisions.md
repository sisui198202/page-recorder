# 🧠 decisions.md

## 🎯 目的

設計・仕様・実装に関する意思決定と、その理由を記録する。

---

## 📌 使い方

- 「なぜそうしたか」を必ず残す
- 後から見て判断理由が分かる状態にする
- 却下案も含めて記録する

---

### D-001: 公開版は書き出しスクリプトで毎回作る

- **決定内容**: `scripts/export-public.sh` で追跡ファイルを書き出し、公開版のコピーにだけ置換を行う
- **背景**: 非公開リポジトリの履歴と作業記録には古いローカルパスや作業メモが残る。開発は今後も続く
- **検討した選択肢**:
  - 案A: 非公開リポジトリを直接書き換え、履歴を消して公開
  - 案B: 手作業で1回だけコピーして整える
  - 案C: 書き出しスクリプトで毎回作る
- **採用理由**: 再実行でき、公開前チェックも毎回自動で行える
- **却下理由**: 案Aは履歴保管領域を書き換え開発記録を失う。案Bは更新のたびに同じ作業と確認が要る
- **影響範囲**: scripts/export-public.sh、publish/
- **関連ドキュメント**:
  - requirements.md: R0
  - design.md: 代替案
- **ステータス**:
  - [x] 確定

### D-002: PDF を公開版から除外する

- **決定内容**: `**/*.pdf` を書き出し対象から外す
- **背景**: 追跡されている PDF は Markdown から生成した派生物で、中に古いローカルパスが含まれうる
- **検討した選択肢**:
  - 案A: PDF も含める
  - 案B: PDF を除外する
- **採用理由**: PDF の中身はスクリプトで置換・検査できない。元の Markdown は公開版に含まれる
- **却下理由**: 案Aは置換漏れを検出できない
- **影響範囲**: 公開版の docs/・plan/・tests/ の pdf フォルダ
- **ステータス**:
  - [x] 確定
- **備考**: 実装中、`perl -0` の各レコード末尾の NUL により `\.pdf$` が一致せず PDF がコピーされた。`chomp` で NUL を外してから判定するよう修正（2026-11-01）

### D-003: 公開版のインストール手順に `--legacy-peer-deps` を付ける

- **決定内容**: 公開版 README・手動テスト手順の `npm ci` を `npm ci --legacy-peer-deps` にする
- **背景**: 公開版で `npm ci` を実行すると、`jest-chrome@0.8.0` の peer dependency（jest ^26 || ^27）と jest 29.7.0 が衝突して ERESOLVE で失敗した（2026-11-01 確認）
- **検討した選択肢**:
  - 案A: 手順に `--legacy-peer-deps` を書く
  - 案B: `.npmrc` に `legacy-peer-deps=true` を追加する
  - 案C: jest や jest-chrome のバージョンを変える
- **採用理由**: 依存関係とテスト環境を変えずに済み、変更が文書だけで完結する。`--legacy-peer-deps` で 20 suites / 394 tests の成功を確認済み
- **却下理由**: 案Bは design に無い新規ファイルで、非公開側のインストール挙動も変わる。案Cは拡張機能の開発環境に影響する
- **影響範囲**: publish/README.public.md、tests/docs/公開版エクスポートの手動テスト手順.md、scripts/export-public.sh の案内文
- **ステータス**:
  - [x] 確定

## 📝 運用ルール

- Decisionは必ずID（D-XXX）で管理する
- 小さな判断でも記録してよい
- 後から変更された場合は履歴を残す
- 過去のDecisionは削除しない
