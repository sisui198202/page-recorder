# A: single 回帰シナリオ分類改善

## 目的

`A: single` の8シナリオを目的別に整理し、実行したい回帰観点を選びやすくする。将来、通常監視フローだけへECサイト・登録URLの選択を追加できる境界を作る。

## 背景

現在は8シナリオが単一の選択リストに並び、通常監視、設定・セレクタ異常、Gmail通知という異なる目的が混在している。シナリオID・設定反映・実行ロジック・自動判定を変えずに、表示上の分類を先に整える。

## 計画

### 1. シナリオの分類情報を定義する

- `SINGLE_TEST_SCENARIOS` の各定義へ、表示用のグループ情報を追加する。
- 既存ID・ラベル・固定設定・自動判定対応・実行actionは変更しない。

| グループ | 対象シナリオ |
| --- | --- |
| 通常監視フロー | `appear`、`disappear`、`initial_detected`、`initial_not_detected` |
| 設定・セレクタ診断 | `keyword_missing_check`、`element_not_found_check`、`pending_error_check` |
| 通知連携 | `gmail_notification_check` |

### 2. popupの選択UIを3グループへ表示する

- 既存の`testScenarioSelect`を維持し、初期HTMLと動的な選択肢再描画の両方で同じ3グループを表示する。
- グループ名は「通常監視フロー」「設定・セレクタ診断」「通知連携」とする。
- 選択値は既存のシナリオIDのままにし、保存済みシナリオの復元、開始ボタン、説明カード、結果カードの既存連携を維持する。

### 3. 回帰契約を追加する

- 8 IDが既存どおり存在し、各IDが正しいグループへ属することを確認する。
- 初期HTMLと動的再描画のグループ・選択肢順が一致することを確認する。
- シナリオID、実行action、自動判定対応、Gmail事前条件の既存契約を維持する。

## 受け入れ条件

- `A: single` の選択UIで、8シナリオを上記3グループとして読める。
- 既存の8シナリオID、固定設定、実行ロジック、自動判定、Gmail通知確認は変わらない。
- popup再表示時に保存済みのシナリオIDを従来どおり復元できる。
- 通常監視フロー以外には、ECサイト・登録URLの選択UIを追加しない。

## スコープ外

- ECサイト・登録URLの選択UI、その選択に応じたテスト設定・手動再現コードの生成。
- シナリオの追加・削除・ID変更、監視ロジック、Gmail送信仕様の変更。

## 将来拡張時の前提

通常監視フローのサイト選択を追加する際は、選択サイトごとに検証URL・セレクタ・キーワード・出現/消失の再現方法を定義できる場合だけ選択可能にする。現在の手動再現コードは日産ページ固定のため、診断とGmail通知のグループへサイト選択を流用しない。
