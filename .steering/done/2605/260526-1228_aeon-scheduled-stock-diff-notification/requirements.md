# requirements.md

## 🎯 目的

AEON 検索結果ページを毎日定時に確認し、前回確認時より商品件数や検知対象が増えた可能性を検出して、後続処理につなげることを目的とした機能が想定される。

---

## 📌 背景

* 現在は在庫検知系の実装内容が後からタスクとして追跡しづらい問題がある
* AEON 検索結果ページの増加検知を、定時実行とログ保存付きで扱いたい要望があった
* 検知後に URL オープンや他拡張機能通知、既存の購入導線連携までつなげるケースが想定される

---

## 👤 ユーザーストーリー

* as a 拡張機能利用者
* I want AEON の対象ページを 13:00 などの定時に監視したい
* so that 商品追加の可能性をすぐ検知し、既存の自動購入導線へつなげられるようにしたい

---

## 🧩 機能要件

* 毎日指定時刻に対象 URL を確認できる可能性があること
* 前回確認時との差分を比較し、増加を判定できる可能性があること
* 増加検知時にログを必ず書き出せること
* 増加検知時に商品 URL を開く挙動を選択できる可能性があること
* 他拡張機能へ検知結果を通知できる可能性があること
* AEON 側の既存 URL トリガーモードと連携できる可能性があること

---

## ⚙️ 非機能要件

* 既存の単一監視 UI と大きく矛盾しないこと
* 定時実行設定が保存され、Service Worker 再起動後も復元されること
* 増加検知がなかった場合は不要な URL オープンや通知を行わないこと

---

## ✅ 受け入れ条件（Acceptance Criteria）

* [ ] 指定時刻実行の可否を確認できる
* [ ] 差分比較の対象と方法を確認できる
* [ ] 増加検知時のログ出力が確認できる

---

## 🚫 スコープ外（Out of Scope）

* AEON 購入フロー本体の新規実装
* 他 EC サイト向けの汎用在庫検知拡張
* 受け入れ条件の最終確定


## 🚧 制約事項

* 本来は branch 作成と steering 作成を先行すべきだが、今回は事後記録である
* 他拡張機能連携は通知先拡張の受信口実装に依存する
* AEON ページ構造変更時は差分検知精度が低下する可能性がある
