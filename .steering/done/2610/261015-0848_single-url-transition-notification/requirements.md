# Requirements: 単独URL状態遷移検知と共有通知統合

## 目的

系統A（単独URL・複数URL）のキーワード監視を、監視開始時の正常な状態を基準にした出現／消失の状態遷移検知へ統一する。検知時は既存の共有Chrome通知を利用し、利用者が監視方式にかかわらず検知を確認できるようにする。

## 背景

- 起点: `plan/todo.md` の「単独URLの状態遷移検知と共有Chrome通知を統合する」および `plan/docs/単独URL状態遷移検知と共通通知統合改善計画.md`。
- 系統B/Cの共有通知基盤は、完了タスク `261013-1442_common-notification-pagerecorder` で既に移行済みである。
- 系統Aは初回状態を永続的な基準として扱わないため、出現／消失の遷移だけを検知する契約を明確にして実装する必要がある。

## ユーザーストーリー

- 在庫監視の利用者として、開始時の状態では誤通知を受けず、在庫状態が変化したときだけ通知を受け取りたい。
- 即座検知を有効にした利用者として、開始時点で条件に一致していれば直ちに通知を受け取りたい。

## 機能要件

- 即座検知OFFでは、初回の正常判定を監視セッションの基準状態として保存し、出現は「なし→あり」、消失は「あり→なし」の場合だけ検知する。
- 即座検知ONでは、初回の条件一致を従来どおり検知対象とする。
- 取得失敗、セレクタ不一致、判定不能では基準状態を更新せず、復旧後の正常判定で遷移を評価する。
- Service Worker の再開後も、進行中セッションの基準状態を引き継ぐ。
- 系統Aの検知は共有Chrome通知を1回だけ表示する。通知失敗は保存、Gmail、外部拡張通知、監視継続を停止させない。
- テストタブに、外部通知・本番baseline更新を伴わず共有Chrome通知を確認できる専用シナリオを追加する。

## 受け入れ条件

- [x] 即座検知OFFの出現監視では、初回の非一致は通知せず、後続の一致で1回だけChrome通知を表示する。
- [x] 即座検知ONの出現／消失監視では、初回の条件一致をChrome通知付きで検知する。
- [x] 消失監視では、初回の一致を基準とし、後続の非一致だけを検知する。
- [x] 取得失敗・セレクタ不一致・Service Worker再開で誤通知または重複通知が発生しない。
- [x] 専用テストシナリオで共有Chrome通知と成功ログを確認できる。
- [x] 既存のB/C共有通知、外部拡張通知、Gmail、保存の契約を回帰させない。

## スコープ外

- 検知キーワード、セレクタ、サイト定義の変更。
- Discordなど受信側拡張の実装・展開。
- Chrome通知以外の通知チャネルの新設。

## 制約事項

- MV3 Service Worker の停止・再開と既存の監視セッション保存方式を維持する。
- background のログは既存の `logger` / `bgLog*` を利用し、生の `console.*` を追加しない。
- 通知、保存、Gmail、外部拡張通知の既存順序と契約を変更しない。
