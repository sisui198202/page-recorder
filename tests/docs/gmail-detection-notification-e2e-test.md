# シナリオ8: Gmail 検知通知 E2E テスト

## 概要

本番に近い環境で在庫検知を自動再現し、Gmail API の送信成功までを自動判定する E2E テストです。受信箱への到着と本文は、読み取り権限を増やさず手動確認します。

## 事前条件

- Google Cloud Console で Gmail API が有効
- manifest の Chrome 拡張機能 OAuth client ID に現在の拡張機能 ID が登録済み
- popup の「Gmail 通知」で有効 + 送信先設定済み + 認証済み（テストメール送信で確認）
- 拡張機能をリロードし、Service Worker Console を開いておく

## テストケース

### 8-A: 自動判定で単一URL監視・検知・Gmail送信

1. popup の「Gmail 通知」が有効かつ認証済みであることを確認
2. popup の「テスト」タブでテストサイト（在庫なしサンプルがあるサイト）とシナリオ8を選び、検知の再現を「自動」にする
3. 「テスト開始（自動判定）」を押す。本番と同じ二層セッションで在庫なしサンプルの監視を開始し、基準取得後に拡張が対象要素へキーワードを追記して在庫ありにする
4. 以下を確認:
   - 結果カードが合格になり、「Gmail 検知送信」が成功している
   - 今回の実行IDに対応する Gmail API 送信成功だけで判定されている
   - HTML 保存、スクリーンショット保存、通常監視終了も成功している
5. 送信先の受信箱で、検知メールが1通届き、日時・検知種別・対象 URL・キーワードを含むことを手動確認する

### 設定・認証が不足する場合

1. Gmail 通知を無効にする、送信先を空にする、またはテストメール成功前の状態にする。
2. シナリオ8の「テスト開始（自動判定）」を押す。
3. 結果カードが「要確認」となり、理由とテストメール送信の案内を表示することを確認する。
4. 通常監視タブが開かず、メールも送信されないことを確認する。

### multiple 6/7: Gmail 検知送信

目的: multiple の開始経路で、在庫なし固定URLを在庫ありへ自動再現した検知メールが、設定ID単位で期待件数だけ送信されることを確認する。

実行:

1. Gmail 通知を有効にし、現在の送信先で「テストメール送信」を成功させる。
2. テストタブの `A: multiple` で、シナリオ5（1件）または6（2件）を選び、「テスト開始（自動判定）」を押す。
3. 結果欄が「成功」になることを確認し、受信箱で同数のメールの到着・本文を確認する。失敗した場合は、結果欄に送信成功の件数（例: 成功 1/2 件）と理由が表示される。
4. 監視タブ作成またはダウンロードで popup が閉じた場合は、再度開き直す。同じテストの結果欄が復元され、実行中なら更新され続けることを確認する。

期待結果:

- シナリオ5は1件、シナリオ6は2件の Gmail API 送信成功（設定ごと）がそろった場合だけ「成功」になる。
- single 8 の検知送信後でも、同じ有効状態・送信先でテストメール成功済みなら開始前確認を通過する。
- 送信先またはGmail有効状態を変更した場合は、テストメールを再送するまで開始しない。

保証範囲:

- 成功は、今回の実行IDに紐づく設定IDごとの Gmail API送信成功と、手動で確認した受信箱の到着・本文に限る。
- Gmail APIの送信成功だけでは、受信箱への到着・本文の正しさを保証しない。これらは手動確認が必要である。
- 「要確認」は、Gmail無効、送信先変更、または現在の設定に対するテストメール成功未確認であり、監視・保存処理を開始していないことを示す。

## 判定基準

### 合格条件

- 検知が発生した
- 結果カードで、今回の実行IDに対応する Gmail API 送信成功を確認できる
- 通常監視の DOM再現、検知、保存、終了が成功している
- 受信箱でメール到着と本文を手動確認できる

### 不合格条件

- Gmail API が `auth_required`、`validation_error`、`api_error` を返す
- 今回の実行IDに対応する送信結果が見つからない
- 受信箱への到着または本文が期待と異なる

## 確認ポイント

| 項目 | 確認方法 |
|------|---------|
| Gmail 有効状態 | popup の「Gmail 通知」トグル |
| 認証状態 | テストメール送信が成功すること |
| Gmail API送信 | 結果カードの「Gmail 検知送信」と今回の実行ID |
| メール到着 | 送信先の受信ボックス（手動） |
| 検知情報 | メール本文の日時、URL、キーワード等（手動） |
| 既存処理 | HTML/スクショ保存、通常監視終了 |

## Gmail 通知が無効または未認証の場合

- シナリオ8では Gmail 通知が無効、送信先未設定、またはテストメール成功が未確認の場合、通常監視を開始せず「要確認」とする。
- 本番 A/B/C 監視における無効時未送信・未認証時の継続は、`gmail-notification-manual-test.md` の「3. 未送信と失敗時の継続」で確認する。
