# ログレベル別表示ガイド

## 目的

popup のログレベル選択肢 `ERROR / INFO / DEBUG` を切り替えたときに、background Service Worker のコンソールで何が表示されるかを実装準拠で整理する。

選択値は `serviceWorkerLogLevel` に保存される。popup を閉じて開き直した場合も、保存済みの値が選択欄へ復元される。

この文書は「レベル別の見え方」の補助ガイドであり、ログ文言の一般方針は [docs/ログ表記ガイド.md](docs/ログ表記ガイド.md) を参照する。

## 対象範囲

- 対象は `src/background/background.js` の `logger` / `bgLogError` / `bgLogWarn` / `bgLogInfo` / `bgLogDebug` と、`monitoringConfigManager.js` の `mcmLogger` を通るログ
- 正本は `LogLevel` 定義、`shouldSuppressLog()`、各 `bgLog*` の出力条件
- `popup.js` や `content-script.js` の生 `console.*` はこの設定で統一制御されない
- 共有ライブラリ読込前の起動ログ、および `executeScript` 内で対象ページに注入する `console.*` はこの設定の対象外
- Service Worker 起動後の `🔧 Service Workerログレベル復元: ...` は、実効モードを確認するためにレベル判定を通さず1回だけ出力する起動診断ログ
- `WARNING` は内部定義 `2` として存在するが、ここでは popup の主要選択肢 `ERROR=1 / INFO=3 / DEBUG=4` に絞って説明する

## INFO / ERROR / DEBUG の見え方

### ERROR

- 設定値: `1`
- 表示するもの: `error`
- 表示しないもの: `warn` `info` `debug`
- 重複抑制: なし

出る例:

- `❌ 監視処理エラー:`
- `❌ HTMLダウンロードエラー:`

出ない例:

- `⏰ ... 監視時間制限に達したため停止`
- `📨 メッセージ受信:`

### INFO

- 設定値: `3`
- 表示するもの: `error` `warn` `info`
- 表示しないもの: `debug`
- 重複抑制: 通常の `info` ログは行わない。`bgLogProgress` を明示した周期進捗だけが対象となる

出る例:

- `⏰ ... 監視時間制限に達したため停止`
- `✅ ... 監視開始完了`
- `✅ [MCM] 監視対象を更新しました:`

出ない例:

- `📨 メッセージ受信:`
- `🔍 ... 設定データ詳細分析:`
- `[MCM] Storage キー移行チェック - 現在の状態:`
- `[MCM] Storage キー移行: 既に移行済み（monitoring_config のみ存在）`
- `📊 ベースライン取得アラーム設定:`
- `⏰ 複数サイト監視アラーム設定:`

補足:

- UI の選択肢名は `INFO` だが、実際には warning ログも表示される

### DEBUG

- 設定値: `4`
- 表示するもの: `error` `warn` `info` `debug`
- 表示しないもの: なし
- 重複抑制: 通常の `info` / `debug` ログは行わない。`bgLogProgress` / `bgLogDiagnostic` を明示したログだけが対象となる

出る例:

- `📨 メッセージ受信:`
- `🔍 ... 設定データ詳細分析:`

出ない例:

- なし

補足:

- 代表例として `logger.debug("📨 メッセージ受信:", request)` のような受信詳細ログも見える
- `mcmLogger` 経由の設定読込・移行確認・整合性確認も見える

## 補足

- background のログは `HH:mm:ss.SSS:` の時刻プレフィックス付きで表示される
- 起動直後の `🔧 Service Workerログレベル復元: DEBUG (4)` を確認すると、以降の DEBUG 詳細ログが出る状態かを判別できる
- `ERROR / INFO / DEBUG` は表示レベル名であり、個々のログ本文に付く絵文字や `[DEBUG]` 文言は既存メッセージごとに異なる
- `shouldSuppressLog()` は、明示した周期進捗・調査詳細を event と scope 単位で抑制する。同じ対象でも 5 秒経過後は再表示される
- `ERROR` と warning ログは重複抑制の対象外
