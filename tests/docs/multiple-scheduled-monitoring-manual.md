# 複数URL監視（A）定時開始 手動テスト

## 前提

- `複数URL監視` に有効な監視対象を1件以上登録する。
- 「時間経過時の監視継続時間（今すぐ・予約共通）」は、確認に十分な時間（例: 1分）に設定する。
- `chrome://extensions` で拡張をリロードし、Service Worker Console を開く。

## 手順

1. `複数URL監視` の `共通時間設定` を開く。
2. `毎日一括開始予約` の `定時監視を有効化` を ON にし、現在時刻より1〜2分後の `監視開始時刻` を指定する。
3. Popup を閉じて開き直し、設定が復元され、`定時監視: 予約中` と `次回実行` が表示されることを確認する。有効な監視対象が0件なら `定時監視: 予約不可` と理由が表示されるため、先に対象を追加・有効化する。
4. 指定時刻まで待機する。手動の `今すぐ一括開始` は押さない。
5. Console に `複数URL監視の定時開始結果` が出て、有効な監視対象のタブ・セッションが開始されることを確認する。
6. 共通の継続時間の満了、または検知後に、各監視が既存の通常複数URL監視と同じ条件で終了することを確認する。

## 期待結果

- A 専用の `dailyMultipleMonitoring` アラームだけが作成され、B の `dailyStockCheck` と C の `dailyStockCheck_<site>` は変更されない。
- Excel取込で有効な対象を追加した場合も、取込完了時にA専用アラームが自動で再同期される。
- 無効な対象は開始されず、有効な対象だけが開始される。
- 定時開始でも、共通の間隔・取得期間・検知・保存設定が手動の `全て開始` と同じように反映される。
- `定時監視を有効化` を OFF にして保存すると、次回実行は `未予約` になり、以後の自動開始は行われない。
- 予約解除は実行中の `今すぐ一括開始` 分を停止せず、`今すぐ一括停止` は予約開始分を停止しない。予約開始分は共通の継続時間で自動終了する。

## 複数URL監視（B）対象別予約表示

1. `複数URL監視` の `B: 対象ごとの毎日開始予約` を開き、開始・終了時刻を設定して対象を追加する。
2. Popup を閉じて開き直す。
3. A と同じ状態カードに `定時監視: 予約中`、対象件数、対象ごとの時間帯、`次回実行` が表示されることを確認する。

### 期待結果

- B の状態カードには `popup-list-watch` の対象だけが表示され、C のサイト定時監視は混在しない。
- B の対象が未登録なら、状態カードには `定時監視: 無効` と未登録の案内が表示される。
- 各対象の `予約を無効化` を押すと、対象の状態が `無効` になり、次回実行から除外される。`予約を有効化` で再び予約対象へ戻る。変更時点で実行中の監視は停止しない。

## 複数URL監視（B）即時監視

1. B の対象一覧で、今すぐ監視する対象だけを選択する。
2. 継続時間を1〜480分で設定し、`選択対象を今すぐ開始` を押す。
3. 即時監視状態に対象名と終了予定が表示されることを確認する。
4. 必要なら同じ対象を選択したまま `選択対象の即時監視を停止` を押す。

### 期待結果

- 対象ごとの開始・終了時刻は即時監視に使われず、開始から指定時間後に終了する。
- 予約が無効な対象も即時開始できる。予約アラームと定時実行は開始・停止で変更されない。
- 同じ対象が定時または即時で実行中の場合は二重開始せず、スキップ件数として表示される。
- B表示中に画面上部の「AI判断サポートファイル」をONにした場合、定時・即時いずれも終了後に`PageRecorder/AI_Support_*.md`がダウンロードされる。未検知で継続時間が終了した場合も対象とする。
- 即時監視のConsoleログは`[immediate]`、`即時監視開始`、`継続時間終了`または`手動停止`と表示され、定時監視の`[schedule:n]`・`監視時間帯終了`とは区別される。
- AI判断サポートの設定表では、キーワードと初回キーワード検知が`対象外`、検知モードが`URL差分（新規商品URL）`となる。継続時間終了は成功（未検知）、新商品検知は成功として表示される。
- サイト・プロファイル・商品取得セレクタ・URLの不整合がある対象は`設定要修正`と理由を表示し、即時監視の選択対象にできない。設定を修正しない限り成功扱いにはならない。
- 実行時に全対象を開始できなかった場合は、開始0件の成功メッセージではなく、対象ごとの開始不能理由を表示する。部分成功時は開始件数とスキップ理由を表示する。

## 実行履歴のチェック詳細

1. 監視中に、Popup 上部の `監視実行状況` を開く。
2. 対象カードの `チェック履歴を表示` を開いたまま、数秒待つ。

### 期待結果

- 実行履歴が自動更新されても、手動で開いたチェック履歴は閉じない。
- 手動で閉じた実行中カードは、次回の自動更新で再展開しない。
