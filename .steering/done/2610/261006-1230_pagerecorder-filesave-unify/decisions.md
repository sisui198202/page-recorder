# Decisions: PageRecorder 保存処理の共有API統一

## 決定事項

### 2026-10-06: 段階的置換アプローチ

**決定**: 30箇所を7 Phase に分割して段階的に置換する

**理由**:
- 一括置換はリスクが高い
- Phase ごとに動作確認できる
- 問題発生時に影響範囲を特定しやすい

**代替案**:
- 一括置換 → リスク高
- 機能追加時に随時置換 → 完了時期不明

## 追加決定

### 2026-10-06: 複数URL監視の定時開始は Popup 設定を正本にする

**決定**: A の定時開始時刻は `multiple_common_settings` に保存し、Popup UI から設定する。

**理由**:
- A の対象URLと共通監視条件はすでに Popup で設定するため、時刻だけを JSON 編集にすると操作体系が分断される。
- C はサイト定義をコード管理する運用だが、A は利用者ごとの監視対象を管理する運用である。

### 2026-10-06: C保存付き差分テストは専用アラームと通知抑止を採用する

**決定**: Cの通常保存経路はテスト専用アラームで実行し、実ファイル保存だけを許可する。

**理由**:
- 実運用の時刻変更やbaseline改変なしで、基準・検知のFileSave経路を再現できる。
- Gmail、Chrome通知、外部拡張通知、検知URL展開による外部副作用を防げる。
