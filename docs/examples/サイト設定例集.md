# サイト設定例集（本拡張機能向け）

## 🎯 概要
このドキュメントは、本拡張機能「Summary AutoReload Downloader」の設定例をサイト別にまとめたものです。各サイトの設定パターンとベストプラクティスを理解し、効率的な監視設定を行ってください。

## 📋 監視パターン分類

### パターン1: 正常 - セレクタ一致 + キーワード一致
**特徴**: 最も一般的で安定した監視パターン
- セレクタが正しく要素を特定
- キーワードが期待通りに検知される
- 監視が正常に継続される

**設定例**:
```yaml
monitorSelector: ".product-button"
monitorKeyword: "カートに入れる"
detectMode: "appear"
```

### パターン2: エラー - セレクタ一致 + キーワード不一致
**特徴**: セレクタは正しいが、キーワードの状態が期待と異なる
- セレクタで要素は見つかる
- キーワードが期待値と異なる
- 監視は継続されるが、期待する動作にならない

**設定例**:
```yaml
monitorSelector: ".stock-status"
monitorKeyword: "在庫あり"
detectMode: "disappear"
# 実際のページでは「在庫切れ」が表示されている
```

### パターン3: エラー - セレクタ不一致
**特徴**: セレクタが要素を見つけられない
- 指定したセレクタで要素が見つからない
- ページ構造の変更やセレクタの誤り
- 監視が即座に終了される

**設定例**:
```yaml
monitorSelector: ".old-selector"  # 存在しないセレクタ
monitorKeyword: "テスト"
# エラー: セレクタが見つからないため監視終了
```

## 📈 監視パターン詳細解説（在庫検知編）

### 🎯 パターン1 vs パターン2: 実用的な使い分けガイド

本拡張機能の**出現検知モード**における「即座検知」設定の違いを、在庫監視の実用場面で解説します。

#### ⚡ パターン1: 出現検知 + 即座検知有効
```
📱 監視開始 → 🔍 即座チェック → [✅一致] 📸即座保存→🛑終了
                              [❌不一致] 📄基準保存→🔄定期チェック
```

**🛒 在庫検知での使用場面**:

1. **限定商品の緊急確認**
   - 商品ページを開いた瞬間に在庫状況を知りたい
   - 例：「在庫あり」が既に表示されているかを即座に判定
   - 結果：一致時は即座に証拠保存して監視終了

2. **現在の在庫状況の瞬間把握**
   - リロードを待たずに現在表示中の状態を確認
   - 例：ページを開いてすぐに「カートに入れる」ボタンがあるか確認
   - 結果：即座に判定→あれば保存、なければ継続監視

3. **素早い判定が必要な場合**
   - 監視時間を短縮したい
   - 現在の状態で十分な情報が得られる場合

**📊 実際のテスト例（Sony Angel Store）**:
```
📍 即座検知有効 - 初回チェック実行
✅ キーワード一致！ {expected: 'カートに入れる', actual: 'カートに入れる'}
📸 スクリーンショット保存完了
📄 HTMLソース保存完了
🛑 キーワード一致 → 監視停止・スクリプト終了
```

#### 🔄 パターン2: 出現検知 + 即座検知無効
```
📱 監視開始 → ⏸️ 初回スキップ → 📄基準保存 → 🔄定期チェック開始
```

**🛒 在庫検知での使用場面**:

1. **確実に最新の在庫情報を取得**
   - キャッシュされた古い情報を避けたい
   - 例：ブラウザキャッシュで「在庫あり」表示だが実際は売り切れ
   - 結果：必ずリロード後の最新状態から監視開始

2. **予約商品の販売開始監視**
   - 販売開始時刻まで「準備中」→「予約受付中」への変化を監視
   - 例：現在は「準備中」だが、販売開始と同時に「予約開始」に変化
   - 結果：確実にリロード後の状態から変化を検知

3. **人気商品の在庫復活監視**
   - 「売り切れ」→「在庫復活」の瞬間を捉えたい
   - 例：現在「売り切れ」表示だが在庫補充のタイミングを監視
   - 結果：定期的なリロードで最新状態をチェック

**📊 実際のテスト例（Sony Angel Store）**:
```
⏸️ 即座検知無効 - 初回チェックスキップ
📄 パターン2: 即座検知無効 → 基準ダウンロード実行
📄 基準ダウンロード開始 {tabId: 1366507345}
📸 基準スクリーンショット保存完了
📄 基準HTMLソース保存完了
✅ 基準ダウンロード完了 → 定期チェック開始
🔍 監視チェック実行中... {interval: 20}
✅ キーワード一致！ {expected: 'カートに入れる', actual: 'カートに入れる'}
```

**🛠️ 手動テスト用の設定（パターン2専用）**:
- **UI設定**: 「**リロード後の待機時間（秒）:**」を設定
- **用途**: リロード後にページ準備が完了したあと、追加待機中にF12でDOM要素を手動変更し、キーワード検知をテスト
- **手順**:
  1. 「**監視開始時の即座検知**」を**無効**（チェックなし）にする
  2. 「**リロード後の待機時間（秒）:**」に待機時間（例: 45秒）を設定
  3. 監視開始後、リロード発生
  4. `waitForPageReady()` によるDOM準備完了後、**追加待機時間中**にF12で指定セレクタの要素を手動編集
  5. テキストを指定キーワードに変更
  6. 待機終了後、検知成功を確認
- **ログ出力**: 10秒ごとのカウントダウン表示で待機状況を確認可能

#### 🎯 選択基準まとめ

| 状況 | 推奨パターン | 理由 |
|------|-------------|------|
| **限定商品チェック** | パターン1（即座検知有効） | 現在の状態を即座に確認 |
| **予約開始監視** | パターン2（即座検知無効） | 確実に最新状態から監視 |
| **在庫復活監視** | パターン2（即座検知無効） | リロードで最新在庫を確認 |
| **現状確認優先** | パターン1（即座検知有効） | 素早い判定が重要 |
| **確実性優先** | パターン2（即座検知無効） | キャッシュを避けて最新情報 |

#### ⚠️ 注意事項
- **パターン1**: 既に目的の状態の場合は即座に終了（継続監視なし）
- **パターン2**: 必ず基準保存を実行（監視開始の証拠を残す）
- **共通**: どちらも検知時はスクリーンショット・HTML保存を実行

## 🔧 UI「監視開始時の即座検知」の挙動詳細

### 概要
UIの「監視開始時の即座検知」チェックボックスの動作仕様について説明します。この設定は監視開始時の動作を制御する重要な機能です。

### チェックあり（即座検知有効）
**動作シーケンス**:
1. 監視開始ボタンクリック
2. **即座に現在のページ状態でキーワード検知実行**
3. キーワード一致 → スクリーンショット・HTMLダウンロード → 監視終了
4. キーワード不一致 → リロード間隔秒後にリロード → 再チェック

**使用場面**:
- 現在のページ状態を即座に確認したい場合
- ページが既に目的の状態になっている場合
- 素早い検知が必要な場合

### チェックなし（即座検知無効）
**動作シーケンス**:
1. 監視開始ボタンクリック
2. **キーワード検知をスキップ（初回チェックなし）**
3. **基準ダウンロードを実行して定期監視へ入る**
4. **次の周期でリロード実行**
5. **`waitForPageReady()` によるDOM準備完了待ち**
6. **必要なら `reloadWaitAfterReload` の追加待機**
7. **その後にキーワード検知実行**
8. キーワード一致 → スクリーンショット・HTMLダウンロード → 監視終了
9. キーワード不一致 → リロード間隔秒後にリロード → 再チェック

**使用場面**:
- 必ずリロード後の状態を確認したい場合
- キャッシュされた古い状態を避けたい場合
- 確実に最新の状態を取得したい場合

### 技術的詳細
- **初回チェック判定**: 監視開始から1秒以内は初回とみなす
- **初回チェック時**: リロードをスキップして現在のページ状態を確認
- **2回目以降**: リロード間隔秒後にリロード → `waitForPageReady()` で準備完了待ち → 必要なら追加待機 → キーワード検知
- **DOM準備完了待ち**: `tab.status` / `document.readyState` / 監視対象DOMの準備を確認する通常処理
- **追加待機**: `reloadWaitAfterReload` を設定した場合だけ入る手動テスト向け待機

### コード実装箇所
- **即座検知有効**: `src/background/background.js:1486-1488`
- **即座検知無効**: `src/background/background.js:1489-1491`

| `stopCount` | 監視回数制限 | 回数制限 |

| 設定キー | 説明 | 対応機能 |
|---------|------|----------|

| `downloadSourceWithoutFooter` | フッター除外 | クリーンHTML |

### 手動テスト設定
| 設定キー | UI表示名 | 説明 |
|---------|---------|------|
| `initialKeywordDetection` | **監視開始時の即座検知** | 監視開始時にキーワードが存在すれば即座に検知・ダウンロード |
| `reloadWaitAfterReload` | **リロード後の待機時間（秒）:** | DOM準備完了後に入れる手動テスト中心の追加待機 |

#### 📝 「リロード後の待機時間（秒）:」の詳細
**用途**: 「監視開始時の即座検知」チェックなし時を中心に使う、手動テスト向けの追加待機時間設定

これは通常のDOM準備完了待ちとは別です。ページの読み込み完了判定は `waitForPageReady()` が先に行い、この設定はその後に止めたいときだけ使います。

**使用方法**:
1. 「**監視開始時の即座検知**」のチェックを**外す**（false）
2. 「**リロード後の待機時間（秒）:**」に待機時間を設定（例: 45秒）
3. 監視を開始
4. **ページリロード後のDOM準備完了 + 追加待機時間中**にF12（開発者ツール）でDOM要素を手動編集
5. UIで指定したセレクタ（`monitorSelector`）の要素のテキストを、指定したキーワード（`monitorKeyword`）に変更
6. 待機時間終了後、キーワード検知が正常に動作することを確認

**ログ表示例**:
```
⏳ リロード後の手動テスト用待機開始: 45秒
⏳ 手動テスト待機中... 残り45秒
⏳ 手動テスト待機中... 残り35秒
...（10秒ごとに表示）
✅ 手動テスト用待機完了 → キーワードチェック開始
```

**注意事項**:
- この設定は**開発・テスト専用**です
- 本番運用時は「**監視開始時の即座検知**」を有効（チェックあり）にし、「**リロード後の待機時間（秒）:**」は使用しない
- 待機中は監視間隔（`interval`）の重複実行が自動的にスキップされます

## ⏱️ 待機の考え方

### 1. 通常のページ準備完了待ち

- `tab.status` や `document.readyState`、必要に応じて監視対象セレクタの出現を確認する基本処理です
- これは手動テスト設定とは無関係に、通常運用でも必要です

### 2. 初回基準化

- `initialKeywordDetection` を無効にすると、監視開始直後は現在状態での即時判定を行わず、基準保存を経由して定期監視へ入ります
- ここでいう「初回基準化」は、毎周期の待機とは別概念です

### 3. リロード後の追加待機

- `reloadWaitAfterReload` は、各周期のリロード後にページ準備完了を待ったあと、さらに止めるための設定です
- 主用途は手動テストであり、通常運用で必須の待機ではありません

### 4. 動的ページの見方

- 重要なのは「静的/動的」というラベルより、`readyState=complete` 後も監視対象要素が遅れて出現・差し替えされるかです
- 将来的には、サイト設定で待機要否を明示し、実行時の `pending` や selector 未出現は補助情報として扱うのが前提です
- `dynamicContent` は補助情報であり、現時点で毎回待機を自動切替する実装はありません

## 🎯 セレクタ設定ガイド

### 基本原則
1. **一意性**: 監視対象の要素を一意に特定できるセレクタ
2. **安定性**: ページ更新後も有効なセレクタ
3. **可読性**: 開発者が理解しやすいセレクタ

### 推奨セレクタパターン
```css
/* IDセレクタ（最も安定） */
#add-to-cart-button

/* クラス + 属性（推奨） */
.product-button[data-product-id="123"]

/* 階層構造（中程度の安定性） */
.container .product-section .button

/* 複合セレクタ（高精度） */
.product-card:not(.disabled) .action-button
```

### セレクタ検証方法
```javascript
// DevToolsコンソールで確認
console.log('要素数:', document.querySelectorAll('.your-selector').length);
console.log('最初の要素:', document.querySelector('.your-selector'));
console.log('テキスト:', document.querySelector('.your-selector')?.textContent);
```

## 🔧 トラブルシューティング

### よくある問題と解決方法

#### 問題1: セレクタが見つからない
**症状**: 監視開始直後に終了
**原因**: セレクタの誤り、ページ構造変更
**解決**: DevToolsでセレクタを確認、更新

#### 問題2: キーワードが検知されない
**症状**: 監視は継続するが変化を検知しない
**原因**: キーワードの表記ゆれ、要素の非表示
**解決**: 実際のページ内容を確認、キーワード調整

#### 問題3: 監視が予期せず終了
**症状**: 設定した時間前に監視終了
**原因**: エラー発生、停止条件の誤設定
**解決**: ログ確認、設定値の見直し

### デバッグ手順
1. **ログ確認**: 拡張機能のログでエラー内容を確認
2. **セレクタ検証**: DevToolsでセレクタの有効性を確認
3. **キーワード確認**: 実際のページ内容と設定値を比較
4. **設定見直し**: 各設定値の妥当性を確認

### 🔍 デバッグログの読み方（v1.7対応）

#### キーワード検知ログの確認
```
🔍 キーワード検知詳細: {
    detected: true/false,           // 検知結果
    keyword: '検索キーワード',        // 設定したキーワード
    selector: 'CSSセレクター',       // 使用したセレクター
    detectMode: 'appear/disappear', // 検知モード
    extractedText: '抽出文字列',     // 実際に取得したテキスト
    hasElement: true/false          // 要素の存在確認
}
```

#### ログパターン別診断
- **`hasElement: false`** → セレクターが無効、要素が見つからない
- **`detected: false, hasElement: true`** → セレクターは正しいがキーワードが一致しない
- **`extractedText`** → 実際に取得された文字列を確認、期待値との比較
- **`📍 即座検知有効`** → 即座検知が動作中
- **`⏸️ 即座検知無効`** → 即座検知がスキップされている
