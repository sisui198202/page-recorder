# requirements.md

## 🎯 目的

既存仕様、特に運用中とみられる定時在庫監視フローを壊さずに、検証基盤・純粋関数の安全網・明確な不要物・巨大ファイル構造の整理を段階的に進められるタスクとして整理することを目的とする。

このタスクでは、`plan/docs/refactor-instructions.md` に記載された改善候補のうち、実装可能な範囲と提案止まりにすべき範囲を切り分けながら、変更しやすく検証可能な状態に近づける作業が想定される。

---

## 📌 背景

* `plan/docs/refactor-instructions.md` では、`npm test` の不整合、`src/background/background.js` の巨大化、未使用コードの残存、ドキュメントと実態の乖離などが整理対象として挙げられている。
* 特に `background.js` には複数の監視系統が共存しており、既存挙動を維持したまま小さく安全に整理する必要がある可能性が高い。
* 既存の定時在庫監視や外部拡張通知は運用中の可能性があるため、見た目の整理よりも「挙動を壊さないこと」「検証可能であること」「状態を正直に保つこと」が優先される想定である。

---

## 👤 ユーザーストーリー

※ 必要に応じて複数記載する

* as a 保守・改善を進める開発者
* I want 既存の監視機能を壊さずに、テスト・不要物整理・構造整理を段階的に進めたい
* so that 今後の修正や検証をより安全に行えるようにしたい

* as a 運用担当者
* I want 定時在庫監視の現行フローが維持されたまま改善が進んでほしい
* so that 日々の監視運用や通知連携に影響を出さずに保守性を上げたい

---

## 🧩 機能要件

* 壊れている、または実態と合っていない検証導線を正直な状態へ修正する作業が含まれる可能性がある。
* 純粋関数に対する最小限のユニットテストを追加し、挙動保全の安全網を用意することが想定される。
* 明確な死コード、不要ファイル、実態追従のみで済むドキュメント差分を整理対象に含める可能性がある。
* `src/background/background.js` の純粋関数群や補助ロジックを、挙動不変を前提に分割しやすい形へ整理することが想定される。
* 単一サイト版と複数サイト版の定時監視パイプライン統合のような高リスク変更は、このタスクでは提案止まりになる可能性が高い。

---

## ⚙️ 非機能要件

* Manifest V3 の制約、および Service Worker の既存動作に配慮する必要がある。
* 定時在庫監視、外部拡張通知、既存のダウンロードや baseline 保存挙動を壊さないことが前提になる想定である。
* 変更は小さな段階に分け、各段階で検証可能であることが望ましい。
* 機密情報の扱いは慎重に行い、承認が必要な変更を勝手に確定しないことが必要である。

---

## ✅ 受け入れ条件（Acceptance Criteria）

* [ ] `refactor-instructions.md` と矛盾しない範囲で、実装対象と提案対象が切り分けられている
* [ ] 既存の定時在庫監視フローを壊さないことを前提に、検証基盤や安全網の改善方針が整理されている
* [ ] 高リスクな構造変更は、承認前に提案扱いとして明示されている

---

## 🚫 スコープ外（Out of Scope）

* 指示書で提案止まりとされている高リスク改修を、この段階で勝手に実装すること
* ユーザー未承認の仕様変更や運用方針変更
* 既存監視系統の廃止判断や統合判断の確定


## 🚧 制約事項

* `PRD > steering > code` と `requirements → design → tasklist → 実装` の順序を守る必要がある。
* 既存仕様、とくに定時在庫監視の現役運用フローは保全優先で扱う必要がある。
* 削除や統合を伴う変更には、承認や追加確認が必要になる可能性がある。
* 実装範囲は `plan/docs/refactor-instructions.md` の記載内容から逸脱しないことが前提となる。

## 🔍 影響範囲（Impact Analysis）

* 影響する機能: 定時在庫監視、レガシー監視、外部拡張通知、設定管理、ログ・ダウンロード、検証フロー
* 影響するファイル: `src/background/background.js`, `src/background/monitoringConfigManager.js`, `src/content/content.js`, `manifest.json`, `package.json`, `tests/**`, `PRD/**`, `plan/docs/refactor-instructions.md` に関連する補助文書
* 影響するユーザー操作: popup での監視設定、定時監視開始、検知時の通知やログ確認、開発時のテスト実行
