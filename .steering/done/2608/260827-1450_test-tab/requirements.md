## 背景

現行 popup は `単一監視` / `複数監視` の2タブ構成で運用しているが、手動テスト時に確認したい情報や補助導線が複数箇所に分散している。
`tests/docs/` に正本の手順はある一方、popup から見た入口や確認順は整理されておらず、開発・検証時の切り分け効率が安定しない。
また、通常利用向けの監視設定 UI と、開発・検証向けの補助導線を同じ場所で持ち続けると責務が曖昧になる。

## 目的

popup に開発者向けの `テスト` タブを追加する前提で、通常監視 UI と責務を分離しつつ、手動テスト開始前の確認導線と補助情報を整理できる状態にする。

## 今回スコープ

1. `テスト` タブの対象ユーザーと役割を定義する
2. `単一監視` / `複数監視` との責務境界を整理する
3. `tests/docs/` を正本とした導線設計の方針を固める
4. popup 上で集約したい確認項目や補助情報の範囲を整理する

## 今回スコープ外

- 一般ユーザー向け正式機能としての公開設計
- background の大規模な制御変更
- storage schema の変更
- external messaging payload の変更
- ダミーデータ投入、強制状態変更、破壊的リセット操作
