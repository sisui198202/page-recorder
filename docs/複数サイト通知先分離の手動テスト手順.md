# 複数サイト監視: 通知先分離の手動テスト手順

`.steering/260602-1432_multi-schedule-diff-detection/tasklist.md` の
「サイトごとに異なる通知先へ送信されること」を確認するための手順書。

対象:

- `aeon-pokemon`
- `toysrus-pokemon`

確認したいこと:

- 検知時に `externalExtensionId` が正しく使われること
- サイトごとに異なる `discordChannelId` が送信されること
- `siteId` がサイト設定どおりに payload に入ること
- 他サイトの `discordChannelId` が混入しないこと
- `urls` に一覧URLではなく新規商品URLだけが入ること
- 初回 baseline 保存時は通知せず、2回目以降の `newUrls` 検知時だけ通知すること

---

## 前提

1. `src/config/scheduled-watch-sites.json` に通知先が設定済みであること
2. 受信側拡張機能が `chrome.runtime.onMessage` で受信できること
3. `chrome://extensions` で PageRecorder と受信側拡張機能をリロード済みであること
4. PageRecorder の Service Worker コンソールを開けること

設定例:

```json
{
  "id": "aeon-pokemon",
  "notification": {
    "notifyOtherExtensions": true,
    "siteId": "aeon",
    "discordChannelId": "1476859251145183253",
    "externalExtensionId": "ibmbjnemcpminbmenepldhockemdpomc"
  }
}
```

```json
{
  "id": "toysrus-pokemon",
  "notification": {
    "notifyOtherExtensions": true,
    "siteId": "toysrus",
    "discordChannelId": "1511979758186008596",
    "externalExtensionId": "ibmbjnemcpminbmenepldhockemdpomc"
  }
}
```

受信側で確認したい payload:

```json
{
  "type": "PAGE_RECORDER_STOCK_DETECTED",
  "source": "PageRecorder",
  "siteId": "aeon or toysrus",
  "urls": ["..."],
  "targetUrl": "...",
  "title": "...",
  "count": 1,
  "discordChannelId": "..."
}
```

---

## 実行場所

| 場所 | 用途 |
|------|------|
| PageRecorder の Service Worker Console | 監視開始、baseline 調整、tick 発火 |
| 受信側拡張機能の Service Worker / background Console | 受信 payload の確認 |

PageRecorder 側:

`chrome://extensions` → PageRecorder → `Service Worker` → `Inspect`

## テスト方針

ページ DOM を直接書き換えず、`scheduledWatchSessions` に保持している
baseline を一時的に 1 件減らして差分検知を強制発火させる。

この方法なら AEON / トイザらスで同じ手順を使える。

流れ:

1. サイトごとに監視開始
2. 初回 tick で baseline 保存
3. そのサイトの session baseline を 1 件減らす
4. 次の tick を手動発火
5. 受信側で `siteId` と `discordChannelId` を確認

---

## 0. 初期化

PageRecorder の Service Worker Console で実行:

```javascript
await chrome.alarms.clearAll();
await chrome.storage.local.remove([
  'scheduledStockLogs',
  'scheduledStockSnapshots',
  'scheduledWatchSessions'
]);
console.log('cleared');
```

期待結果:

- 既存アラームが消える
- 古い baseline / session / log が消える

## 1. 受信側のログ準備

受信側拡張機能の Console を開き、通知受信ログを見られる状態にする。

最低限、下記の項目が見えればよい。

- `siteId`
- `discordChannelId`
- `urls`
- `count`

必要なら受信側で一時的に以下のようなログを入れる。

```javascript
chrome.runtime.onMessage.addListener((message, sender, sendResponse) => {
  console.log('received', message);
  sendResponse({ ok: true });
});
```

## 2. `aeon-pokemon` の通知先確認

### 2.1 監視開始

PageRecorder の Service Worker Console で実行:

```javascript
chrome.alarms.create('dailyStockCheck_aeon-pokemon_0', {
  when: Date.now() + 1000
});
```

数秒待ってから session を確認:

```javascript
await chrome.storage.local.get(['scheduledWatchSessions', 'scheduledStockSnapshots']);
```

期待結果:

- `scheduledWatchSessions['aeon-pokemon']` が存在する
- `baselineUrls` に 1 件以上入る
- `scheduledStockSnapshots` に AEON URL の baseline が保存される
- この時点では受信側拡張に通知が飛ばない

### 2.2 baseline を 1 件減らす

```javascript
(async function () {
  const SITE_ID = 'aeon-pokemon';
  const store = await chrome.storage.local.get([
    'scheduledWatchSessions',
    'scheduledStockSnapshots'
  ]);

  const sessions = store.scheduledWatchSessions || {};
  const snapshots = store.scheduledStockSnapshots || {};
  const session = sessions[SITE_ID];

  if (!session || !session.baselineUrls || session.baselineUrls.length < 2) {
    console.error('baselineUrls が不足しています');
    return;
  }

  session.baselineUrls = session.baselineUrls.slice(0, -1);
  session.baselineCount = Math.max(0, Number(session.baselineCount || 0) - 1);
  sessions[SITE_ID] = session;

  const key = session.comparisonKey;
  if (snapshots[key] && Array.isArray(snapshots[key].urls) && snapshots[key].urls.length >= 2) {
    snapshots[key] = {
      ...snapshots[key],
      count: Math.max(0, Number(snapshots[key].count || 0) - 1),
      urls: snapshots[key].urls.slice(0, -1)
    };
  }

  await chrome.storage.local.set({
    scheduledWatchSessions: sessions,
    scheduledStockSnapshots: snapshots
  });

  console.log('baseline reduced', {
    siteId: SITE_ID,
    baselineUrls: session.baselineUrls.length,
    baselineCount: session.baselineCount
  });
})();
```

期待結果:

- `aeon-pokemon` の baseline が 1 件少なくなる
- 他サイトの session / snapshot は変化しない

### 2.3 tick を手動発火

```javascript
chrome.alarms.create('stockWatchTick_aeon-pokemon', {
  when: Date.now() + 1000
});
```

期待結果:

- PageRecorder 側に `🎉 [aeon-pokemon]` の検知ログが出る
- `📨 他拡張通知完了` が出る
- 受信側で message を 1 件受け取る

### 2.4 受信 payload 確認

受信側で以下を確認:

- `message.siteId === 'aeon'`
- `message.discordChannelId === '1476859251145183253'`
- `message.type === 'PAGE_RECORDER_STOCK_DETECTED'`
- `message.urls.length >= 1`
- `message.urls.every(url => url.includes('/product')) === true`
- `message.urls` に一覧ページURLが混ざっていない
- `message.discordChannelId !== '1511979758186008596'`

## 4. 合格条件

以下をすべて満たせば合格:

- `aeon-pokemon` 検知時に `discordChannelId = 1476859251145183253` が送られる
- `toysrus-pokemon` 検知時に `discordChannelId = 1511979758186008596` が送られる
- `aeon-pokemon` の payload に `siteId = aeon` が入る
- `toysrus-pokemon` の payload に `siteId = toysrus` が入る
- 両方とも `externalExtensionId = ibmbjnemcpminbmenepldhockemdpomc` に送られる
- 互いのチャンネル ID が混入しない

---

## 5. トラブルシュート

### `baselineUrls が不足しています`

原因:

- 初回 tick がまだ終わっていない
- 対象サイトの一覧取得に失敗している

対処:

- 数秒待ってから `scheduledWatchSessions` を再確認する
- 対象サイトの `baselineUrls.length` が 2 以上になってから再実行する

### 受信側に何も届かない

確認点:

- `notifyOtherExtensions` が `true` か
- `externalExtensionId` が正しいか
- 受信側拡張機能が起動しているか
- PageRecorder 側に `📨 他拡張通知完了` または失敗ログが出ているか

### `discordChannelId` が入らない

確認点:

- `scheduled-watch-sites.json` の `notification.discordChannelId` に文字列が入っているか
- テスト前に拡張機能をリロードしたか

### 他サイトの値が混ざる

確認点:

- テスト前に `scheduledWatchSessions` を消しているか
- 別サイトの session を同時に加工していないか
- 受信側で直近 message を見ているか
