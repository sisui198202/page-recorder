# 要件: Service Worker ログレベル統一

## 背景

`plan/todo.md` の「ログレベル設定を改善する」を実施する。定期的な設定読込・アラーム再設定の詳細ログが INFO に混在しており、検知・通知などの運用上重要なイベントを追いにくい。

## 受け入れ条件

1. `background.js` と `monitoringConfigManager.js` の通常経路のログは、既存のログレベル判定を通る。
2. 定期ポーリング、設定読込、移行済み確認、アラーム設定などの詳細は DEBUG とする。
3. 監視開始・終了、検知、外部通知成功、ユーザー操作結果は INFO 以上で確認できる。
4. 継続可能な異常は WARN、処理失敗は ERROR とする。
5. ロガー初期化前の起動ログ、および `executeScript` 内で対象ページに出すログは対象外として、理由を文書化する。
6. ログレベル別表示ガイドとログ表記ガイドを実装に合わせて更新する。
7. 自動テストと静的確認を実行し、Chrome 手動確認手順を残す。
8. 手動確認で判明したテストシナリオ1の失効した日産商品URLを、有効な固定テスト対象へ更新し、出現・消失・初回未検知の自動再現が対象商品の在庫状態に依存しないようにする。
9. popup を閉じて開き直しても、保存済みの `ERROR / INFO / DEBUG` 選択値を正しく表示する。
10. Service Worker 起動時に、復元した実効ログレベルを1回だけ表示する。

## 承認

2026-10-14 に提示済みの実装計画に対して、ユーザーから「Implement the plan.」の承認を得た。
