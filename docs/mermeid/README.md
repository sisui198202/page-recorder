# Mermaid 図

拡張機能の主要フローを、文章より短時間で追えるようにするための図置き場です。
この README は単なる目次ではなく、図の構造定義と更新基準の正本として扱います。

## 基本方針

- まず全体図で責務境界と主要接続をつかむ
- 次に抽象フロー図でユースケース単位の大まかな流れを追う
- 最後に具体フロー図で実ファイル・実 API・保存先・通知境界まで確認する
- フロー変更を伴う実装では、コード変更とあわせて関連図とこの README の更新要否を確認する

## 3 層構造

### 1. 全体図

- 目的: コンポーネント境界・責務・主要接続の把握
- 粒度: 機能群どうしの関係をつかめる粒度に留める
- 対象:
  - `コンポーネント図.md`

### 2. 抽象フロー図

- 目的: ユースケース単位の大まかな処理流れを把握する
- 粒度: 実装詳細を入れすぎず、「どこで何をするか」が追える程度に保つ
- 対象:
  - 現時点では該当図なし。必要になったら全体図と具体図の中間粒度で追加する

### 3. 具体フロー図

- 目的: 実ファイル・主要 API・保存/通知/分岐まで追える詳細を示す
- 粒度: 実装調査や変更影響確認に使える粒度で記述する
- 対象:
  - `即座取得フロー.md`
  - `キーワード監視フロー.md`
  - `複数監視フロー.md`
  - `定時在庫監視フロー.md`
  - `定時ベースライン取得フロー.md`
  - `定時在庫検知と通知フロー.md`
  - `複数監視設定のExcel入出力フロー.md`
  - `EC在庫セレクタ同期フロー.md`

## 図ごとの内容ルール

- 抽象フロー図は実装詳細を入れすぎない
- 具体フロー図は実ファイル名・主要 API 名・保存先・通知境界を明示する
- 1 図 1 責務を保ち、分岐が増えすぎたら別図に分割する
- 図の詳細説明や読み順は、この README に集約する

## 現在の読み順

- `コンポーネント図.md` で全体像を確認する

- `定時在庫監視フロー.md` で定時実行の仕組みを確認する
- `定時ベースライン取得フロー.md` で baseline の作られ方を確認する
- `定時在庫検知と通知フロー.md` で検知後の証跡保存と通知を確認する
