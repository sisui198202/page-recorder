## 2. 未完了課題の詳細

### 2.1 複数URL監視UI主導線化

#### 背景

2026-08-29 時点の実装では、`複数URL監視` と `単一URL監視` タブ内の `EC監視サイト + 監視URL登録` は別系統である。
`docs/実装済/ec-monitoring-ui-enhancement.md` により、ECサイト定義と `監視URL登録` の基盤は整っている。一方で popup 上の主作業は、複数の監視対象を一覧で確認し、開始停止し、状態を把握する流れへ寄せた方が運用に合うため、今後の課題は `複数URL監視` を主導線として再定義することとする。

#### 現状

- `単一URL監視` タブには `EC監視サイト` と `監視URL登録` があり、EC向けの監視対象登録はここで行える
- ECサイト定義は `src/config/ec-sites.json` で管理される
- `checkAutoFill()` は「ECサイトが 1 件だけ ON のときのみ」自動補完し、複数ON時は `monitorSelector` と `monitorKeyword` を空に戻す
- `複数URL監視` タブには `共通監視設定` `共通時間設定` `全体制御` `監視対象リスト` `📊 設定管理` がある
- `監視URL登録` が保持するのは `siteId + url` であり、任意名・個別検知モード・個別編集を持つ `監視対象リスト` の完全代替ではない
- popup 上で複数対象の一覧確認、開始停止、状態把握をひとまとまりに扱えるのは現状 `複数URL監視` 側である

#### 期待状態

- popup の初期主導線が `複数URL監視` であると明文化されている
- 主作業が `一覧確認 / 開始停止 / 状態把握` であると整理されている
- `共通監視設定` `共通時間設定` `監視対象リスト` `全体制御` `📊 設定管理` が主改善対象として扱われる
- `単一URL監視` タブ内の `EC監視サイト` と `監視URL登録` は、個別確認・EC補助導線として位置づけられる
- 旧見送り項目だった `一括開始 / 一括停止 / サマリー表示 / 監視対象リスト強化` が再評価対象に戻されている

#### 要件

| 要件ID | 要件                                                                                           | 優先度 |
| ------ | ---------------------------------------------------------------------------------------------- | ------ |
| F1     | popup の初期主導線を `複数URL監視` として扱う                                                  | 必須   |
| F2     | 主作業を `一覧確認 / 開始停止 / 状態把握` として整理する                                       | 必須   |
| F3     | `共通監視設定` `共通時間設定` `監視対象リスト` `全体制御` `📊 設定管理` を主改善対象として扱う | 必須   |
| F4     | `単一URL監視 + EC監視サイト + 監視URL登録` を個別確認・EC補助導線として扱う                    | 必須   |

#### 再評価対象

| 項目                    | 判断       | 理由                                                                                             |
| ----------------------- | ---------- | ------------------------------------------------------------------------------------------------ |
| 一括開始 / 一括停止     | 再評価対象 | popup 主導線を `複数URL監視` に置くなら、全体制御の中心操作として再検討対象になる                |
| サマリー表示            | 再評価対象 | 主作業に `状態把握` を含めるため、一覧上で何を集約表示するかを設計フェーズで再検討する必要がある |
| `監視対象リスト` の強化 | 再評価対象 | 主画面として扱う以上、表示粒度や編集性を改善対象から外せない                                     |

#### 仕様判断メモ

- 主運用は `複数URL監視`
- `監視対象リスト` は主画面
- `全体制御` と `📊 設定管理` は中核操作
- `単一URL監視` は個別確認・EC補助導線
- `checkAutoFill()` は ECサイトが 1 件だけ ON のときのみ自動補完し、複数ON時は `monitorSelector` と `monitorKeyword` を空に戻す。このため、`EC監視サイト + 監視URL登録` は複数対象の主一覧操作の代替ではなく、ECサイトごとの設定入力を省力化する補助導線として扱う
- `監視URL登録` が保持するのは `siteId + url` であり、複数URL監視リストの任意名・個別検知モード・個別編集の完全代替ではないため、主画面は引き続き `監視対象リスト` とする

## 5. 本拡張の責務範囲外の不足機能

以下は購入フロー全体の不足機能であり、本拡張の責務範囲外。
`PageRecorder` は情報収集と通知イベント生成までを担い、通知先最適化や `AutoCartAgent` 連携判断は受信側拡張の課題として扱う。

| 機能                     | フェーズ | 担当                                              |
| ------------------------ | -------- | ------------------------------------------------- |
| セッション維持           | 購入準備 | `auto_login_targettime` 拡張検討                  |
| 在庫検知後の通知先最適化 | 購入実行 | 受信側拡張 (`main_discord_post_url_monitor` など) |
| 在庫検知→直接カート投入  | 購入実行 | 受信側拡張 / `AutoCartAgent` 側で判断             |
| 購入確定自動化           | 購入確定 | 新規拡張機能検討                                  |
| 重複購入防止             | 購入実行 | 統合管理機能検討                                  |
| フォーム自動入力         | 申込実行 | 新規拡張機能検討                                  |
