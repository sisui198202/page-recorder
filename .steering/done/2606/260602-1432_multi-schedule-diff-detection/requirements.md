# Requirements: 定時差分検知の複数設定対応

## 目的

現在「1つしか設定できない」定時差分検知を、**複数のサイト・URLに対して設定できる**ようにする。

## 背景

- 現在の定時差分検知（監視ウィンドウ機能）は、popup の「指定URL」で1つのURLのみを監視対象にできる
- 複数のECサイト（AEON以外）や、同一サイトの複数検索条件を同時監視したいニーズがある
- 設定を `.json` ファイルで管理することで、柔軟な設定変更が可能になる

## 現状の理解

### 現在の仕組み

- `monitoring_config.single_config` または popup の「指定URL」で1つの監視URLを設定
- `scheduledStockSnapshots` に URL をキーとしてスナップショットを保存
- `dailyStockCheck` アラームで定時開始
- `stockWatchTick` アラームで定期チェック
- 1つの URL に対して監視ウィンドウを開き、差分検知を行う

### 問題点

- 監視対象が1つに限定されている
- popup UI で複数設定を管理しにくい
- サイトごとの設定（セレクタ、検知ロジック等）をハードコードしている部分がある

## 要求仕様

### 必須要件

1. **複数URL対応**: 2つ以上の監視URLを同時に設定・実行できる
2. **JSON設定ファイル**: サイトごとの設定を `.json` ファイルで定義できる
3. **サイト別設定**: 各サイトに対して以下を個別に設定できる
   - 監視URL
   - セレクタ（商品リンク抽出用）
   - 監視時間帯（開始・終了時刻）
   - リロード間隔
   - 有効/無効フラグ

### 任意要件

- popup UI での複数設定表示・編集
- 設定のインポート/エクスポート
- サイトテンプレート（AEON, ヨドバシ等の事前定義）

## 受け入れ条件

- [ ] 2つ以上のURLを同時監視できる
- [ ] `.json` ファイルで設定を定義・読み込みできる
- [ ] 各サイトの監視を個別に有効/無効にできる
- [ ] 既存のAEON監視機能が引き続き動作する
- [ ] 設定変更時に拡張機能のリロードで反映される

## 制約事項

- Chrome拡張機能 Manifest V3 の制約に従う
- Service Worker の寿命を考慮した設計にする

## 決定事項（元・未確定事項）

- [x] 複数サイトの同時監視時、タブ管理をどうするか → **並列**（各サイトが独立したタブを持つ）
- [x] 各サイトの通知先（Discord チャンネル等）の分離が必要か → **分離必要**（`discordChannelId`フィールドで設定）
- [x] JSONファイルの配置場所 → **`src/config/`**
