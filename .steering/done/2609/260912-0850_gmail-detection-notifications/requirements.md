# requirements — gmail-detection-notifications

## 目的

PageRecorder の A（キーワード）・B/C（新規商品 URL）本番検知時に、利用者が popup で設定した宛先へ Gmail 通知を送れるようにする。

## 背景

既存の Chrome 通知・保存・外部拡張通知を維持したまま、検知結果をメールでも確認できる経路を追加する。OAuth トークンと送信先はソースコードおよび Git 管理ファイルに保存しない。

## 要件

- Gmail API を使い、A の単一・複数キーワード検知、B の単一サイト差分検知、C の複数サイト差分検知でメールを送信する。
- popup に Gmail 通知の有効/無効、送信先メールアドレス、テスト送信、直近送信結果を表示する。設定は `chrome.storage.local` の `gmailNotificationSettings`、結果は `gmailNotificationLastResult` に保存する。
- 初期値は無効・送信先空とする。テスト送信は対話認証を許可し、本番検知は非対話認証だけを使う。
- 本番メールには日時、検知種別、対象 URL、サイト名、キーワードまたは増加件数、新規 URL（最大 10 件）を含める。
- 自動再現・安全テスト・テストシナリオ・監視時間満了・未検知・エラーでは送信しない。例外としてシナリオ8だけは、利用者が事前に Gmail 有効化・有効な送信先・テストメール成功を確認した場合に、通常の single 監視と DOM 自動再現を通じて実メールを1通送信する。テスト起点は非永続の送信抑止フラグで明示的に抑止する。
- Gmail 送信の失敗は監視、保存、Chrome 通知、外部拡張通知を停止させず、background の既存ログ基盤で記録する。

## 受け入れ条件

- Gmail メッセージ生成、宛先検証、UTF-8 件名、認証/API 成否をユニットテストで確認できる。
- A/B/C の本番検知で共通送信関数を 1 回だけ呼び、非検知・タイムアウト・エラー・各テストでは呼ばれない。
- popup の設定保存・復元、テスト送信中/成功/失敗の表示と `sendGmailTestEmail` 応答を確認できる。
- シナリオ8は Gmail API 送信成功を今回の実行IDに紐付けて自動判定し、設定・認証が不足する場合は監視を開始せず要確認を表示できる。受信箱への到着確認は手動確認として残す。
- Chrome 実機で初回認証、テストメール、A/B/C 検知、無効時未送信、認証切れ時の継続を手順化して確認できる。

## スコープ外

- Gmail API 以外のメールプロバイダ、複数宛先、メール受信・返信機能。
- 既存の Chrome 通知、ダウンロード、外部拡張通知の仕様変更。
