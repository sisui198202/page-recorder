# requirements.md

> 🔍 PageRecorder をポートフォリオとして GitHub で公開できる状態に整える（公開操作そのものは行わない）。

## 🎯 目的

PageRecorder を、第三者に見せられるポートフォリオとして公開できる状態にする。個人環境の情報を取り除き、何を解決するツールで、どう作ったかが README の冒頭で伝わるようにする（仮）。

---

## 🎯 プロダクト概要

- **解決する課題**: GitHub のプロフィールに今の開発実績が公開されておらず、技術力を示せない
- **対象ユーザー**: リポジトリを閲覧する技術者
- **成功指標**: 公開前チェック（ローカルパス・秘密情報・個人情報）がすべて通り、README の冒頭だけで概要・構成・テスト・開発の進め方が分かる

---

## 📌 背景

- GitHub プロフィールの公開リポジトリは Karabiner 設定と TODO アプリのみ
- chromeExtensions 配下の5リポジトリを比較した結果、テスト20ファイル・321コミットがあり、秘密情報が履歴に入っていない PageRecorder が公開候補になった
- 事前調査（2026-11-01、追跡ファイルを名前と件数のみで確認）の結果:
  - `client_secret_*.json` は `.gitignore` で除外済み、履歴にも無い
  - ホームディレクトリの絶対パス（ローカルパス）が 27 ファイルにある（docs・tests・scripts・.steering/done など）
  - Google OAuth クライアントIDが 3 ファイルにある（`manifest.json`、`.gitignore`、`.steering/done/2609/260912-0850_gmail-detection-notifications/design.md`）。Chrome 拡張の client_id は秘密情報ではないが、公開版ではユーザー自身のIDに差し替える形が一般的
  - README は機能の羅列が中心で、閲覧者向けの要約・構成図・テストの説明が無い。LICENSE が無い

## 🧩 機能要件

- R0: 公開版は、履歴を持たない**公開用の新しいリポジトリ**として作る。今の非公開リポジトリ（履歴・`.steering/done/` などの記録）は書き換えず、開発用としてそのまま使う
- R1: 公開版のファイルから、個人環境のローカルパス（`$HOME/...`）を汎用的な表記に置き換える（非公開リポジトリ側は変更しない）
- R2: 公開版の `manifest.json` の OAuth クライアントIDをプレースホルダー（例: `YOUR_CLIENT_ID`）に置き換え、README に利用者が自分のIDを設定する手順を書く。非公開版は今のIDのまま
- R3: 公開版 README の冒頭に、閲覧者向けの要約（解決する課題、主な機能、構成、テスト、開発の進め方・生成AIの活用）を追加する
- R3-2: 公開版 README の「先着検知向けの高頻度セッション」や AutoCartAgent への通知など、買い占め目的と受け取られうる表現を、「Webページの変化検知・通知」といった技術寄りの表現に言い換える
- R4: 公開版に MIT の LICENSE を追加する
- R5: 公開版を対象に公開前チェック（ローカルパス・秘密情報・個人情報・外部Webhook）を実行し、結果を記録する
- R6: 公開版には `src/`・`tests/`・`PRD/`・README などに加え、`.steering/`・`docs/`・`plan/`・`download/` も含める（ユーザー指定）
- R7: 買い占めを連想させる購入フロー系の資料（`参考/購入フロー_拡張機能対応表.md` など）は公開版から除外する。対象ファイルの一覧は design で確定する

---

## ⚙️ 非機能要件

- セキュリティ: 認証情報・トークン・Webhook URL・個人のメールアドレスを公開対象に含めない
- 既存動作: 拡張機能の動作（監視ロジック・background I/O・外部拡張への通知境界）を変えない
- 既存テスト: Jest のテストがすべて通る状態を保つ

- [x] 公開対象に認証情報・トークン・Webhook URL・個人メールアドレスが含まれていない
- [x] OAuth クライアントIDの扱いが決まっており、README に設定手順がある

- [x] `npm test` が成功する
- [x] 拡張機能を読み込み直しても、popup が開き既存の監視設定が表示される

## 🚫 スコープ外（Out of Scope）

- GitHub での公開操作（visibility の変更、新規リポジトリ作成、push）。ユーザーが実施または別途明示指示する
- 他の4リポジトリ（AutoCartAgent、auto_login_targettime、discord_post_url_monitor、discord_channel_exporter）の変更
- 拡張機能の機能追加・不具合修正

## 🚧 制約事項

- 既存の履歴には古いローカルパス等が残るため、HEAD の修正だけでは履歴からは消えない
- `.steering/done/`・`docs/実装済/` は履歴保管領域で、通常は内容を書き換えない（ドキュメント運用ルール）
- 共有設定（`ec-sites.json` 等）は親リポジトリの同期スクリプトで生成される配布コピーを含む

---

## 🔍 影響範囲（仮）

- 公開版（新しいリポジトリ用のコピー）の README.md、manifest.json（client_id）、ローカルパスを含む docs / tests / scripts / .steering
- 非公開リポジトリ側は、本タスクの steering と `plan/todo.md` 以外は変更しない想定（公開版を作る手順やスクリプトを置く場合は design で決める）
- 拡張機能の実行ロジック（src/）は変更しない
