# A/B 定時実行設定と現在時刻プリセット

## 目的

単一URL A の毎日開始予約を追加し、単一URL A/B の予約操作を統一し、複数URL B の開始・終了時刻を現在時刻から素早く入力できるようにする。

## 方針

単一URL A/B は予約ON/OFFの保存で即時にアラームを再同期する。A は指定URLを毎日開始でき、開始時刻は現在＋2分で設定できる。B はURL・商品取得セレクタがそろった予約だけを作成し、予約とは独立して今すぐ開始・停止できる。即時監視は初期値3分の指定時間だけ実行する。複数URL A は今すぐ一括監視と毎日一括開始予約を共通の継続時間で終了させ、開始元ごとに状態と停止操作を分離する。複数URL B は対象別の開始・終了時刻だけを使う定時監視専用とし、日付またぎは受け付けない。

複数URL A の予約状態は「毎日一括開始予約」設定欄の開始時刻直後に、単一URLと同じ状態カードで表示する。運用サマリーには予約状態を重複表示しない。

状態応答が軽量化されても、複数URL A の予約可否と対象件数は `monitoring_config.multiple_configs` の正本から算出する。

複数URL A の毎日一括開始予約は、開始時刻を現在＋2分に設定して即時保存・再同期できる。

複数URL B の対象別毎日開始予約は、A と同じ状態カードで定時予約状態・時間帯・次回実行を表示する。カードは既存の定時状態取得から B の対象だけを抽出し、C のサイトは表示しない。

複数URL B の各対象は、対象行の操作から予約を有効・無効化できる。変更後は既存の定時アラームを再同期し、実行中の監視は止めない。

複数URL B の即時監視は、対象一覧で明示選択した保存済み対象だけを開始する。継続時間は開始から1〜480分（初期値3分）で、定時設定の開始・終了時刻は使わない。即時開始・停止は予約設定、予約アラーム、定時実行と独立する。

複数URL B のAI判断サポートファイルは、B表示中に有効化したB専用設定を使用する。定時・即時とも開始時の設定をセッションに固定し、検知の有無にかかわらず終了時に実行履歴付きMarkdownをダウンロードする。即時監視のログは`[immediate]`、継続時間終了、手動停止を使い、定時の予約枠ログと区別する。

## 起点

2026-10-08 のユーザー指摘「単一URL A に定時実行設定がない」「複数URL A に現在時刻から設定があり、B にない」。
