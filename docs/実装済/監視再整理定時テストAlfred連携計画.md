# 監視再整理・定時テスト拡張・Alfred連携計画

## 目的

監視機能を A（キーワード監視）、B（単一サイト定時検証）、C（複数サイト定期運用）として明確に分離し、定時監視を安全に確認できる短時間テストと、実運用寄りの Alfred 補助フローを整備する。

## 方針

- A はユーザー指定の検索結果・一覧 URL を対象にし、検索語から URL を生成しない。
- B は popup 保存設定の単一サイト定時監視、C は `src/config/scheduled-watch-sites.json` を正本にした読み取り専用の複数サイト定期運用とする。
- B/C テストは本運用の session、alarm、baseline と完全に分離し、副作用（通知、検知 URL 表示、ダウンロード、baseline 永続化）を発生させない。
- C の実通知確認は popup テストに混在させず、Alfred `tes'` のバックアップ・絞り込み・時刻設定・復元フローで行う。

## 完了条件

- popup で A/B/C の役割、C の状態と再同期、B/C の安全テストを操作できる。
- B 無効時にも C のアラーム同期が維持される。
- 自動テストで UI、メッセージ、拒否条件、テストの無副作用と cleanup を確認できる。
- Alfred の正本・生成物・手順書が新しい background メッセージに対応する。
