# Gmail 検知通知 手動テスト

## 事前条件

- Google Cloud Console で Gmail API が有効であり、manifest の Chrome 拡張機能 OAuth client ID に現在の拡張機能 ID が登録されている。
- 拡張機能をリロードし、Service Worker Console を開く。
- テスト用の送信先メールアドレスを用意する。OAuth Client Secret JSON は拡張機能へ読み込ませず、Git に追加しない。

## 1. 初回 OAuth とテストメール

1. popup の「Gmail 通知」で送信先を入力し、必要に応じて有効にする。
2. 「テストメール送信」を押す。
3. Google の認証画面が表示されたら、送信元に使う Google アカウントを選んで許可する。
4. popup が「送信成功」になり、送信先に `[テスト] PageRecorder Gmail 通知` が届くことを確認する。
5. popup を閉じて再度開き、有効状態・送信先・直近結果が復元されることを確認する。

## 2. A/C 本番検知

1. Gmail 通知を有効にし、認証済みの状態にする。
2. A の単一または複数 URL キーワード監視で本番の検知条件を発生させる。
3. C の複数サイト定時監視で新規 URL 差分を発生させる。B安全テストはターゲットセレクタ未確定のため、Gmail検知送信の確認対象外とする。
4. 各検知でメールが 1 通だけ届き、日時、検知種別、対象 URL、サイト名、キーワードまたは増加件数、新規 URL が含まれることを確認する。
5. Service Worker Console に Gmail 成功ログがあり、既存の保存、Chrome 通知、外部拡張通知も従来どおり完了することを確認する。

## 3. 未送信と失敗時の継続

1. Gmail 通知を無効にして同じ検知を発生させ、メールが届かない一方で既存の検知処理が完了することを確認する。
2. popup の A テストシナリオ、multiple テスト、B/C 安全テストを実行し、メールが送信されないことを確認する。
3. Google アカウントの拡張機能アクセスを取り消すか、認証済みでない Chrome プロフィールで本番検知を実行する。
4. OAuth ダイアログが自動で表示されず、Service Worker Console に認証要の警告が残り、監視・保存・Chrome 通知・外部拡張通知が継続することを確認する。
5. popup の「テストメール送信」から再認証できることを確認する。

## 記録

- 受け入れ条件に関わる実機結果は、日時、対象（テスト送信/A/C/無効/認証切れ）、結果、主要根拠を `ai-notes.md` に 1〜4 行で要約する。B安全テストのGmail検知確認は対象外とする。
- 期待結果との差分が再現する場合は、ログ根拠を添えて `plan/todo.md` に別タスク候補として起票する。
