# Product Requirements - PageRecorder

## 概要

`PageRecorder` は、ページの HTML・スクリーンショット取得、キーワード変化監視、定時在庫監視、新商品 URL 抽出を行う Chrome 拡張機能である。現行の主運用は `chrome.alarms` を使う定時在庫監視フローとする。

### 対象ユーザー

- 商品ページや一覧ページの変化を継続監視したいユーザー
- 在庫変化や新規 URL 出現を検知し、後続の外部拡張へ通知したいユーザー
- ページ変化の証跡として HTML・スクリーンショットを保存したいユーザー

### 主要機能

1. 即座取得による HTML・スクリーンショット保存
2. 単一 URL / 複数 URL のキーワード監視
3. popup 設定ベースの単一サイト定時在庫監視
4. `scheduled-watch-sites.json` ベースの複数サイト定時在庫監視
5. `ec-sites.json` ベースの EC 監視 UI
6. 一覧ページからの新商品 URL 自動抽出
7. 検知結果の外部拡張通知
8. テストタブによる手動確認補助

## 1. コア機能要件

### 1.1 popup 基本操作

#### シナリオ: popup 表示

```gherkin
Given Chrome拡張機能が有効である
When ユーザーが拡張機能アイコンをクリックしたとき
Then popup が表示される
And 現在の監視状況が確認できる
And 主な監視導線と設定導線が表示される
```

#### シナリオ: 監視モード切替

```gherkin
Given popup が開かれている
When ユーザーが監視モードを切り替えたとき
Then single と multiple の状態が切り替わる
And 必要に応じて既存設定が移行される
And 選択中モードに対応する UI が表示される
```

### 1.2 単一監視

#### シナリオ: 即座取得

```gherkin
Given 監視対象ページを開いている
When ユーザーが即座取得を実行したとき
Then 現在のページから HTML が保存される
And スクリーンショットが保存される
And 実行結果が popup またはログで確認できる
```

#### シナリオ: 単一 URL キーワード監視

```gherkin
Given single 監視設定が保存されている
And セレクタ、キーワード、検知モードが指定されている
When ユーザーが監視開始を実行したとき
Then キーワード状態の確認が開始される
And 検知時に HTML とスクリーンショットが保存される
And 監視状態が更新される
```

### 1.3 複数 URL 監視

#### シナリオ: 複数監視設定の管理

```gherkin
Given multiple 監視モードが選択されている
When ユーザーが監視対象リストを操作したとき
Then 監視対象を追加、編集、削除できる
And 個別の有効/無効を切り替えできる
And 監視対象ごとに名前と条件を保持できる
```

#### シナリオ: 複数監視の実行

```gherkin
Given 複数の監視対象が設定されている
When ユーザーが一括開始を実行したとき
Then 有効な監視対象ごとに監視が開始される
And 各対象の検知結果が独立して扱われる
And 一部失敗時も他の対象の状態管理を継続できる
```

### 1.4 定時在庫監視

#### シナリオ: 単一サイト定時監視

```gherkin
Given popup 設定ベースの定時監視が有効である
When スケジュール時刻になったとき
Then Service Worker が監視処理を開始する
And 在庫状態の確認結果が保存または通知される
```

#### シナリオ: 複数サイト定時監視

```gherkin
Given scheduled-watch-sites.json に有効なサイト設定がある
When 各サイトのスケジュール時刻になったとき
Then サイトごとの定時監視が実行される
And 必要に応じて baseline が取得される
And 在庫差分または URL 差分が判定される
And 検知時に通知イベントが生成される
```

### 1.5 EC 監視 UI

#### シナリオ: EC サイト設定補助

```gherkin
Given ec-sites.json にサイト定義が存在する
When ユーザーが EC 監視 UI を操作したとき
Then サイト一覧が表示される
And サイト単位で ON/OFF を切り替えできる
And 単一選択時に監視条件が自動補完される
And サイト紐づけ URL を登録できる
```

### 1.6 新商品 URL 自動取得

#### シナリオ: 一覧差分からの URL 抽出

```gherkin
Given 一覧ページを対象に定時監視している
When baseline と比較して新しい商品 URL が増えたとき
Then 新規 URL だけが抽出される
And 検知結果として保存または通知される
```

### 1.7 外部拡張通知

#### シナリオ: 検知結果通知

```gherkin
Given 検知イベントが発生した
And 通知先拡張機能IDが設定されている
When 外部通知が実行される
Then 検知結果が external messaging で送信される
And 送信成否がログまたは状態に反映される
```

### 1.8 テストタブ

#### シナリオ: 取得方式診断

```gherkin
Given テストタブの「取得方式診断」サブタブを開いている
When ECサイトの在庫あり・なしサンプルを一括診断する
Then 選択サイトと直近の一括診断結果が復元される
And 保存成果物を確認できる
When 任意ページを単件診断する
Then 専用の対象URL、セレクタ、キーワードだけを使用する
And 通常監視の設定や開始状態は変更されない
```

#### シナリオ: 手動確認補助

```gherkin
Given テストタブが利用可能である
When ユーザーが single 向けテストシナリオを適用したとき
Then 対応する監視設定が一括で反映される
And 適用前の設定が single_config_backup に退避される
And 復元操作で元の設定に戻せる
```

#### シナリオ: multiple 4番の明示的な自動再現

```gherkin
Given `manual_appear_two_urls` が選択されている
When ユーザーが「自動で再現コードを挿入」をONにして開始する
Then リロード後の待機中に各監視tabへ固定のDOM変更が注入される
And 注入失敗したtabだけが停止する
And このON/OFFは監視設定へ保存されない
```

## 2. 品質要件

### シナリオ: MV3 準拠

```gherkin
Given Chrome 拡張として動作する
When 監視機能を実行したとき
Then Manifest V3 の制約内で動作する
And Service Worker 前提の構成を崩さない
```

### シナリオ: ローカル完結

```gherkin
Given 設定保存や検知処理を行う
When 通常機能を利用したとき
Then データはローカル保存を前提に処理される
And 外部サーバー必須の依存を持たない
```

### シナリオ: ログ運用

```gherkin
Given 重要な操作またはエラーが発生した
When background がログを出力するとき
Then logger または bgLog 系を通して記録される
And デバッグに必要な情報が残る
And 不要な機密情報は出力しない
```

### シナリオ: 手動回帰可能性

```gherkin
Given 監視ロジックまたは通知導線を変更した
When 回帰確認を行うとき
Then tests/docs の手順に沿って確認できる
And 必要なら手順書が更新される
```
