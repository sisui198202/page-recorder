---

## 1. 概要

本ドキュメントでは、PageRecorderの在庫検知機能について以下を説明する。

1. PRDに基づく理想的な完成形
2. 現状の実装状況
3. 理想と現状の差異（未実装・改善候補）
4. 監視設定のベストプラクティス

## 4. 理想と現状の差異

### 4.1 ギャップ一覧

| カテゴリ     | 項目                           | 理想                           | 現状                     | 優先度 |
| ------------ | ------------------------------ | ------------------------------ | ------------------------ | ------ |
| **監視精度** | セレクタ自動検証               | 全サイトでsite_capture検証済み | 一部サイトのみ           | 中     |
|              | 在庫状態の両パターン検証       | 在庫あり/なしの両HTML確認済み  | サイトによる             | 中     |
| **UI/UX**    | 複数監視の情報設計             | 監視対象の階層的表示           | フラットリスト           | 低     |
|              | 設定のインポート/エクスポート  | Excel完全互換                  | 実装済み（改善余地あり） | 低     |
| **通知**     | 通知先の柔軟な設定             | サイト×チャンネル単位          | 基本実装済み             | 低     |
|              | 通知テンプレートのカスタマイズ | ユーザー定義可能               | 固定フォーマット         | 低     |
| **運用**     | Fetch監視の診断自動化          | 新サイト追加時に自動診断       | 手動診断                 | 中     |
|              | 監視失敗の自動リカバリ         | エラー後の自動再試行           | 手動対応                 | 中     |

### 4.2 改善候補の詳細

#### A. セレクタ検証の網羅性

**理想:**

- 全対応サイトで `site_capture/02_product_in_stock/` と `site_capture/03_product_out_of_stock/` が存在
- `{site}_site_structure/yaml/` に検証済みセレクタが記録されている

**現状:**

- 主要サイトは検証済み
- 一部サイトはセレクタのみ定義、実HTML未検証

**改善案:**

- 新サイト追加時のsite_capture取得を必須化
- yaml未検証セレクタへの警告表示

#### B. Fetch監視の適用拡大

**理想:**

- タブを開かないFetch監視がデフォルト
- サイト特性に応じた自動判定

**現状:**

- デフォルトはDOM監視（`fetchMode.enabled: false`）
- 手動診断でFetch可否を判定

**改善案:**

- `在庫Fetch一括診断`の自動実行
- 診断結果に基づくfetchMode自動設定

#### C. 監視失敗時のリカバリ

**理想:**

- 一時的なネットワークエラー後の自動再試行
- Cloudflare待機の自動対応

**現状:**

- Cloudflare対応ガイドは存在
- 自動リカバリは限定的

**改善案:**

- リトライ回数と間隔の設定
- pending状態からの自動復帰

## 5. 監視設定のベストプラクティス

### 5.1 個別商品ページ監視

特定の商品URL（例: `https://shop.example.com/item/12345`）を監視する場合。

#### 5.1.1 単一URL監視

**推奨設定:**

```javascript
{
  "mode": "single",
  "single_config": {
    "target": "specified_url",
    "url": "https://shop.example.com/item/12345",
    "selector": "#cart-button",           // カートボタンのセレクタ
    "keyword": "カートに入れる",           // 在庫ありテキスト
    "detection_mode": "appear",           // 出現を検知
    "interval": 10,                       // 10秒間隔
    "reload_wait": 2,                     // リロード後2秒待機
    "immediate_check": true               // 開始時に即座チェック
  }
}
```

**ユースケース:**

- 限定商品の発売開始監視
- 再入荷タイミングの検知
- 価格変更の監視

**注意点:**

- `appear`（出現検知）: 在庫なし→在庫あり を検知
- `disappear`（消失検知）: 在庫あり→在庫なし を検知
- セレクタは`ec-sites.json`の定義を参照して設定

#### 5.1.2 複数URL監視（個別商品）

**推奨設定:**

```javascript
{
  "mode": "multiple",
  "multiple_configs": [
    {
      "id": "item-001",
      "name": "商品A 在庫監視",
      "enabled": true,
      "url": "https://shop.example.com/item/001",
      "selector": ".stock-status",
      "keyword": "在庫あり",
      "detection_mode": "appear",
      "interval": 15,
      "reload_wait": 2
    },
    {
      "id": "item-002",
      "name": "商品B 在庫監視",
      "enabled": true,
      "url": "https://shop.example.com/item/002",
      "selector": ".stock-status",
      "keyword": "在庫あり",
      "detection_mode": "appear",
      "interval": 15,
      "reload_wait": 2
    }
  ]
}
```

**ユースケース:**

- 同一シリーズの複数商品を同時監視
- 代替商品を並列で監視
- 複数店舗の同一商品を監視

**注意点:**

- 監視対象が多いほどリソース消費が増加
- 5〜10件程度を上限の目安とする
- 長時間監視には系統C（定時監視）を推奨

### 5.2 キーワード検索結果ページ監視

商品一覧ページ（例: `https://shop.example.com/search?q=ポケモン`）を監視する場合。

#### 5.2.1 単一検索結果ページ監視

**推奨設定（系統A）:**

```javascript
{
  "mode": "single",
  "single_config": {
    "target": "specified_url",
    "url": "https://shop.example.com/search?q=ポケモン",
    "selector": ".search-result-count",     // 検索結果件数
    "keyword": "件",                         // 件数表示を含むテキスト
    "detection_mode": "appear",              // 変化を検知
    "interval": 30,
    "reload_wait": 3
  }
}
```

**より高精度な設定（系統C）:**

```json
// scheduled-watch-sites.json
{
  "id": "example-pokemon",
  "name": "Example ポケモンカード検索",
  "enabled": true,
  "url": "https://shop.example.com/search?q=ポケモン",
  "selectors": {
    "productLinks": "a.product-link", // 商品リンク
    "itemCount": ".search-count", // 件数表示
    "screenshotTarget": ".search-results" // スクショ対象
  },
  "baselineTime": "09:00",
  "schedules": [
    {
      "startTime": "09:30",
      "endTime": "12:00",
      "intervalSeconds": 60
    }
  ],
  "notification": {
    "openProductUrl": false,
    "notifyOtherExtensions": true,
    "siteId": "example",
    "externalExtensionId": "ibmbjnemcpminbmenepldhockemdpomc"
  }
}
```

**ユースケース:**

- 新商品入荷の検知
- 特定キーワードの商品追加監視
- 在庫復活の定期チェック

**注意点:**

- 件数だけでなく、新規URLの抽出を併用すると精度向上
- baselineTimeは商品追加前の安定した時刻を設定
- 検索結果が動的に変わるサイトは短い間隔で誤検知リスクあり

#### 5.2.2 複数検索結果ページ監視

**推奨設定（系統C - scheduled-watch-sites.json）:**

```json
{
  "sites": [
    {
      "id": "aeon-pokemon",
      "name": "イオン ポケモンカード",
      "enabled": true,
      "url": "https://aeonretail.com/search?q=ポケモン",
      "selectors": {
        "productLinks": "li.product__item a",
        "itemCount": "span.product__search--num"
      },
      "baselineTime": "10:00",
      "schedules": [
        { "startTime": "10:30", "endTime": "18:00", "intervalSeconds": 120 }
      ],
      "notification": {
        "notifyOtherExtensions": true,
        "siteId": "aeon",
        "discordChannelId": "channel-001"
      }
    },
    {
      "id": "sevennet-pokemon",
      "name": "セブンネット ポケモンカード",
      "enabled": true,
      "url": "https://7net.omni7.jp/search?q=ポケモン",
      "selectors": {
        "productLinks": ".productListItem a",
        "itemCount": ".searchResultCount"
      },
      "baselineTime": "10:00",
      "schedules": [
        { "startTime": "10:30", "endTime": "18:00", "intervalSeconds": 120 }
      ],
      "notification": {
        "notifyOtherExtensions": true,
        "siteId": "sevennet",
        "discordChannelId": "channel-002"
      }
    }
  ]
}
```

**ユースケース:**

- 複数ECサイトの同一商品カテゴリを横断監視
- 発売日に複数サイトを同時チェック
- 定期的な在庫状況の網羅的確認

**注意点:**

- 各サイトのbaselineTimeを揃えると比較しやすい
- discordChannelIdでサイト別の通知先を分離可能
- intervalSecondsはサイト負荷を考慮して60秒以上を推奨

## 6. 監視タイプ別の選択ガイド

### 6.1 判断フロー

```
監視対象は何か？
│
├─ 特定の商品ページ（URL固定）
│   ├─ 1件のみ → 系統A single
│   ├─ 2〜5件 → 系統A multiple
│   └─ 6件以上 or 長時間 → 系統C
│
└─ 検索結果ページ（一覧）
    ├─ 1サイトのみ → 系統A single または 系統C
    ├─ 複数サイト → 系統C（推奨）
    └─ 件数＋新規URL検知 → 系統C（必須）
```

### 6.2 系統別の特性比較

| 観点     | 系統A（単一/複数） | 系統C（定時監視）          |
| -------- | ------------------ | -------------------------- |
| 監視間隔 | 5秒〜              | 30秒〜                     |
| 最大件数 | 〜10件程度         | 制限なし                   |
| 監視時間 | 1分〜8時間         | 無制限（スケジュール制御） |
| URL抽出  | キーワードのみ     | 新規URL差分検知可          |
| 設定方法 | popup UI           | JSON設定ファイル           |
| 主な用途 | 短期集中監視       | 定常運用                   |

### 6.3 設定のベストプラクティスまとめ

| シナリオ                     | 推奨系統        | 推奨間隔  | 備考                       |
| ---------------------------- | --------------- | --------- | -------------------------- |
| 発売開始時刻の数分間集中監視 | A-single        | 5〜10秒   | 高頻度セッション           |
| 複数商品の再入荷待ち         | A-multiple      | 15〜30秒  | 最大5件程度                |
| 毎日の新商品チェック         | C               | 60〜120秒 | baselineで差分検知         |
| 複数サイト横断監視           | C               | 120秒〜   | scheduled-watch-sites.json |
| Cloudflare対応サイト         | A-single（DOM） | 30秒〜    | Fetch非推奨                |
