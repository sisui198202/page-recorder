# requirements — multi-monitor-popup-redesign

## ステータス

更新済み。`design.md` と整合する前提・要件を整理した状態。

## 起点

- `plan/todo.md` の `複数サイト一括監視UI改善`
- `plan/docs/missing-features-roadmap.md`
- 今回の起票は、既存の未コミット計画差分を `複数URL監視` 主導線化として再定義したうえで実施

## 背景

2026-08-29 時点の popup には、`複数URL監視` と `単一URL監視` 内の `EC監視サイト + 監視URL登録` という別系統の監視導線がある。
`ec-monitoring-ui-enhancement` により EC 補助導線の基盤は整った一方、複数対象を一覧で確認し、開始停止し、状態を把握する主作業は `複数URL監視` 側に集約されている。
このため、次フェーズでは `複数URL監視` を popup の主導線として再定義し、`単一URL監視` は個別確認・EC補助導線として位置づけ直す必要がある。

## 目的

`複数URL監視` を popup の主導線にする前提で、一覧確認と開始停止を主作業として扱えるように requirements / design / tasks を切り分けて進められる状態を作る。

## 今回確定する前提

- popup 初期主導線は `複数URL監視`
- 主作業は `一覧確認 / 開始停止 / 状態把握`
- `単一URL監視` は個別確認・EC補助導線
- 変更方針は `主作業最短` を優先し、既存タブ構成は維持したまま `複数URL監視` を初期表示で主導線化する
- 主画面上部の状態把握は `件数中心サマリー` とし、表示項目は `監視中件数 / 停止中件数` とする
- `単一URL監視` には主導線明示型の短い補助説明を追加する
- `監視対象リスト` の常時表示項目は最小化し、`キーワード` と `セレクタ` は一覧常時表示から外す
- `共通監視設定` `共通時間設定` `📊 設定管理` は折りたたみ対象とし、`監視対象リスト` と `全体制御` は常時表示とする
- `全体制御` の `全て開始` `全て停止` は今回も必要な中核操作として維持する
- `サマリー表示` は今回の popup に実際に追加する
- `複数URL監視` 側にも `EC監視サイト` の選択 UI を置く
- `複数URL監視` の `EC監視サイト` は、`新しい監視対象を追加` 時に `src/config/ec-sites.json` の `セレクタ / キーワード` をモーダルへ自動補完するために使う
- 折りたたみ状態は保存し、popup を閉じても次回復元する

## 今回の設計判断

- 最適化対象は `主作業最短` とし、一覧確認・開始停止・状態把握を最少操作で行えることを優先する
- 主導線の変更は `初期表示だけ変更` を基本とし、既存タブ構成の全面再編は行わない
- 主画面サマリーは `件数中心サマリー` とし、`監視中件数 / 停止中件数` を表示する
- `単一URL監視` の基準文言は `通常運用は複数URL監視です。ここでは個別確認や EC 向け補助設定を行います。` とする
- `単一URL監視` から `複数URL監視` へ移動する専用ボタンやリンクは追加しない
- `監視対象リスト` の常時表示は `名前 / 状態 / URL / 開始 / 停止 / 編集 / 削除` とする
- `キーワード` と `セレクタ` の確認・変更は既存の `編集` 導線で行う
- `全て開始` と `全て停止` は `全体制御` 内の必須操作として残す
- `サマリー表示` は今回の実装対象に含める
- `監視対象リスト強化` は今回確定した最小表示項目への整理までを実装対象とし、それ以上の拡張は扱わない
- `複数URL監視` の `EC監視サイト` は複数選択トグルではなく、追加時に使う 1 サイト選択とする
- 選択したサイトは `src/config/ec-sites.json` のサイト定義から `セレクタ / キーワード` を参照し、新規監視対象追加モーダルへ自動入力する
- `監視対象リスト` は引き続き `URL ごとの監視実体` を扱う一覧とする
- 折りたたみ対象は `共通監視設定` `共通時間設定` `📊 設定管理` のみとする
- 折りたたみ対象 3 セクションの初期状態は `閉じる` とする
- 折りたたみ状態は `chrome.storage.local` 等に保存し、popup 再表示時に復元する
- 折りたたみ UI は既存 `section` 単位の軽量追加とし、別モーダル化やタブ増設は行わない
- 折りたたみ UI は見出し行全体を開閉トリガーにし、右端に `開く / 閉じる` ラベルを出す
- 閉じた状態では本文のみ `display: none` にする
- `📊 設定管理` は `全体制御` の内側ではなく独立 section とする

## 変更対象と完了条件

- 変更対象は popup の表示構成と文言に限定する
- 外部 API、保存スキーマ、background I/O 境界、通知境界は変更しない
- 既存の `開始 / 停止 / 編集 / 削除` 操作導線は維持する
- 完了条件は、主導線変更が UI 整理に留まり、既存監視操作の回帰がないこと

## 確認したい受け入れ観点

- popup 初期表示で `複数URL監視` が主導線として見えること
- `件数中心サマリー` として `監視中件数 / 停止中件数` が表示されること
- `単一URL監視` に補助説明が表示されること
- `複数URL監視` に `EC監視サイト` の 1 サイト選択 UI が表示されること
- `新しい監視対象を追加` 時に、選択サイトの `セレクタ / キーワード` がモーダルへ自動補完されること
- `監視対象リスト` に `名前 / 状態 / URL` と 4 操作ボタンが見え、`キーワード / セレクタ` が常時表示されないこと
- `全体制御` と `監視対象リスト` が常時表示されること
- `共通監視設定` `共通時間設定` `📊 設定管理` が開閉でき、再度 popup を開いても直前状態が復元されること
- `編集` 導線から従来どおり `キーワード / セレクタ` を確認・変更できること
- `全て開始 / 全て停止 / 状態更新` と各行 `開始 / 停止 / 編集 / 削除` が回帰しないこと
