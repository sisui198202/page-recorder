# multiple の Gmail 検知送信シナリオ

## 目的

multiple 監視の検知経路で Gmail API 送信を安全に検証できる、1 件送信と 2 件送信の専用自動シナリオを追加する。

multiple 6/7 の開始前確認は、テストメール送信が成功した設定を参照し、後続の検知送信によって誤って未確認扱いにならないこと。また、シナリオ詳細には実行される Gmail・監視・保存設定を表示する。

## 背景

既存 multiple テストは Gmail 通知を常に抑止しており、multiple 経路の Gmail 検知送信を再現・確認する手段がない。本タスクはユーザー提示の実装計画を起点とし、通常監視と既存テストの通知境界を維持する。

直近送信結果をテストメール成功確認にも流用すると、single 8 などの検知送信が成功した時点で `source: test` が失われ、multiple 6/7 が誤って「要確認」になる。この確認状態は送信結果と分離する。

popup が監視タブ作成やダウンロードで閉じた場合も、`A: multiple` を選択していれば、`multiple_test_scenario_state.scenario_id` を正本として最後に開始したシナリオ6/7を再表示する。Chrome セッション中の Gmail 判定結果も同じシナリオに限り再表示し、実行中ならポーリングを再開する。未保存・不正なID・別サブタブまたは別シナリオ選択時は既定表示または非表示とする。
