# 設計: 複数URL監視の情報設計改善

## 画面構成

1. 運用サマリー: 監視中・待機中・無効の件数と、毎日開始予約の状態・時刻・対象件数・次回実行時刻を表示する。
2. 全体制御: 既存の全て開始、全て停止、状態更新を維持する。
3. 監視対象: 追加元サイトの選択と追加ボタンを一覧見出しに集約し、対象を状態順のコンパクトカードで表示する。
4. 詳細設定: 監視条件と実行・予約設定を既存の折りたたみとして表示する。
5. 詳細・管理: Excel入出力とC: 複数サイト定期運用を折りたたんで表示する。

## 状態表示と整列

- `running` を監視中、`enabled` かつ非稼働を待機中、`enabled === false` を無効として集計する。
- 表示順は `running`、待機中、無効とし、同順位は入力配列の順番を保つ安定整列にする。
- 既存の `multiple_configs` の保存順・設定値は変更しない。

## 互換性

- 既存の要素ID、`multiple_common_settings`、`multiple_configs`、background message は保持する。
- 予約状態は既存 `scheduledWatch` の情報のみを表示し、操作・保存は従来どおり実行・予約設定内で行う。

## 検索結果・一覧ページ群

- `multiple_list_watch_configs` に、サイトID、検証済みプロファイルID、同一ホストのURL、対象別の時間枠・間隔を保存する。
- backgroundは設定をC互換のサイト定義へ解決し、既存の差分検知・アラーム・baseline基盤を対象IDごとに再利用する。
- CのJSON定義とは異なるIDプレフィックスでsession・アラームを分離し、既存Cを変更しない。
