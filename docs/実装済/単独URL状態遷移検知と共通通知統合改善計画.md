# 単独URL状態遷移検知と共通通知統合改善計画

## 背景

popup の出現検知・消失検知は「キーワードなし→あり」「あり→なし」の状態遷移として説明されている。一方、現行の単独URL／複数URLキーワード監視は、各回の現在状態だけで検知を決めるため、監視開始時の状態を基準にした遷移判定になっていない。

また、共有 `ChromeNotify` は定時検索結果ページ監視（系統C）の在庫差分通知だけで使用している。利用者にとっては監視方式によらず、検知時に統一されたChrome通知を受け取れる方が分かりやすい。

## 目標

- 個別商品ページのキーワード監視を、初回状態を基準とする出現／消失の遷移検知にする。
- 単独URL、複数URL、単一サイト定時監視（系統B）、複数サイト定時監視（系統C）の検知通知を共有通知ポリシーへ集約する。
- Chrome通知の失敗が監視、保存、Gmail、外部拡張通知を停止させないようにする。
- テストタブから、共有Chrome通知を実際に確認できる専用シナリオを提供する。

## 方針

### 状態遷移の扱い

- 監視開始時の最初の取得結果を、監視セッションごとの基準状態として保存する。MV3 Service Worker の停止・再開後も引き継げるよう、既存のセッション永続化先に状態を保存する。
- `監視開始時の即座検知` がONの場合は、初回取得でも条件一致を検知・通知する。これは現在のUI説明どおり、在庫ありを直ちに知るための明示的な例外とする。
- 即座検知がOFFの場合は、初回取得では通知せず基準状態だけを保存する。以後の取得で、出現検知は`なし→あり`、消失検知は`あり→なし`になったときだけ検知する。
- セレクタ不一致、取得失敗、判定不能は基準状態を上書きせず、復旧後の正常な結果だけで遷移判定する。

### 通知ポリシー

- `showInventoryDetectionNotification(event)` をBackgroundの共通通知ポリシーとして設け、すべての検知経路は検知結果をイベントとして渡す。
- キーワード状態の検知はタイトルを `在庫を検知`、一覧URLのbaseline差分検知は `在庫差分を検知` とする。本文には対象名、検知方式、URLまたは新規件数を含める。
- 共通ポリシーが `ChromeNotify.show()` を呼び、成功時は `[chrome-notify]`、失敗時はWARNで確認できるようにする。
- 外部拡張通知・Gmail通知・保存・検知URL展開は既存の有効設定と順序を維持する。Chrome通知の重複を防ぐため、同一検知イベントに対する表示は1回だけとする。

### テスト導線

- テストタブに、実際のChrome通知を表示する「共有検知通知テスト」を追加する。テスト用のDOM状態変更で出現／消失を再現し、外部拡張送信と本番baseline更新は行わない。
- 既存のC安全テストは、Chrome通知を抑止する現在の安全性を維持する。通知確認は上記の専用シナリオで行う。

## 実施手順

1. キーワード監視セッションに前回のキーワード状態と初回判定済み状態を追加し、単独URL・複数URL・系統Bで共通に利用する。
2. 現在状態だけで検知している箇所を、即座検知設定と前回状態に基づく遷移判定へ置換する。
3. キーワード検知とURL差分検知のイベント形式を定義し、共通通知ポリシーへ接続する。
4. 既存のC在庫差分通知を共通ポリシー経由に移行し、外部・Gmail・保存処理の回帰を確認する。
5. テストタブの専用通知シナリオ、単体テスト、手動テスト手順を追加する。

## 受け入れ条件

- 即座検知OFFの個別商品ページで、初回の在庫なしは通知せず、後続の在庫ありで1回だけ `在庫を検知` が表示される。
- 即座検知ONの個別商品ページで、初回の在庫ありは直ちに `在庫を検知` が表示される。
- 消失検知で、在庫ありから在庫なしへの遷移だけを検知する。
- 複数URL・系統B・系統Cも、それぞれの検知時に共有 `ChromeNotify` 経由で通知される。
- Service Worker再開、取得失敗、セレクタエラーで誤通知・重複通知が発生しない。
- テストタブの専用シナリオで通知表示と `[chrome-notify] 通知作成成功` を確認できる。

## 対象外

- 検知キーワード、セレクタ、サイト定義の変更。
- Discordを含む受信側拡張の実装・展開。
- Chrome通知以外の通知チャネルを新設すること。
