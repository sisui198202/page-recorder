# System Role Definition - PageRecorder

## 概要

本ドキュメントは、PageRecorder の購入フロー全体における役割と責務範囲を定義する。

---

## 1. 購入フローにおける位置づけ

### 1.1 4フェーズ構成

商品購入フローは以下の4フェーズで構成される。

| フェーズ | 名称 | 概要 |
|---------|------|------|
| 1 | 情報収集 | 利益商品・入荷時間帯・在庫状況の把握 |
| 2 | 購入準備 | ログイン・URL準備・認証準備 |
| 3 | 購入実行 | カート投入・数量選択・配送選択 |
| 4 | 購入確定 | 決済処理・注文確定・完了確認 |

### 1.2 本拡張機能の担当フェーズ

**情報収集フェーズ（第1フェーズ）を担当**

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│   情報収集    │ → │   購入準備    │ → │   購入実行    │ → │   購入確定    │
│     ✅       │    │      -       │    │      -       │    │      -       │
│【本拡張担当】 │    │【他拡張担当】 │    │【他拡張担当】 │    │  ❌ 未対応   │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

---

## 2. 役割詳細

### 2.1 基本情報

| 項目 | 内容 |
|------|------|
| **フェーズ** | 情報収集 |
| **主機能** | ページソース・スクリーンショット取得、在庫状態差分検知、通知イベント生成 |
| **対象サイト** | 任意のWebサイト |
| **用途** | ページ変化の記録、入荷パターン分析、在庫状態変化の検知 |

### 2.2 主要機能一覧

| 機能 | 説明 |
|------|------|
| ページソース取得 | HTMLソースの自動ダウンロード |
| スクリーンショット取得 | ページ画像の自動キャプチャ |
| 即座取得 | JavaScript実行後のDOM状態をキャプチャ |
| キーワード監視 | 出現検知・消失検知 |
| 単一URL監視 | 1つのURLを監視 |
| 複数URL監視 | 複数URLを同時監視 |
| 定時在庫監視 | `chrome.alarms` ベースで単一/複数サイトを定時監視 |
| 新商品URL自動取得 | 一覧ページから新規商品URLを抽出 |
| 外部拡張通知 | 検知結果を外部拡張へ通知 |
| 監視間隔カスタマイズ | 15秒～300秒のスライダー調整 |
| 取得期間設定 | 1分～60分のスライダー調整 |
| Excel出力・入力 | 監視設定のエクスポート・インポート |

## 3. 対応パターン

### 3.1 購入パターン分類

本拡張機能は、以下の3パターンで使用される。

| パターン | 条件 | 本拡張の用途 |
|---------|------|-------------|
| C | 傾向予測あり + URL判明 | 入荷パターン分析用データ収集 |
| D | 傾向予測あり + URL不明 | 一覧監視による新商品URL抽出と通知イベント生成 |
| I | 複数サイトを並行監視したい | 複数サイト定時在庫監視と通知イベント生成 |

### 3.2 パターンC詳細

**シナリオ**: 過去の傾向から「10:00〜12:00の間に入荷する」と予測。商品URLは既知（再販など）。

```
┌─────────────────────────────────────────────────────────────────────┐
│ 情報収集        │ 購入準備          │ 購入実行          │ 購入確定    │
├─────────────────┼───────────────────┼───────────────────┼─────────────┤
│ 傾向分析        │ 時間帯前ログイン  │ 在庫検知          │ 決済・確定  │
│ Discord履歴分析 │ 商品ページ監視    │ → カート投入      │             │
├─────────────────┼───────────────────┼───────────────────┼─────────────┤
│ PageRecorder    │ auto_login_       │ 受信側拡張        │ ❌ なし     │
│ (本拡張)        │ targettime        │                   │             │
└─────────────────┴───────────────────┴───────────────────┴─────────────┘
```

**本拡張の役割**: 商品ページの状態監視、記録、通知イベント生成

### 3.3 パターンD詳細

**シナリオ**: 過去の傾向から入荷時間帯を予測。どの商品が入荷するかも不明。

```
┌─────────────────────────────────────────────────────────────────────┐
│ 情報収集        │ 購入準備          │ 購入実行          │ 購入確定    │
├─────────────────┼───────────────────┼───────────────────┼─────────────┤
│ 傾向分析        │ 時間帯前ログイン  │ 新商品検知        │ 決済・確定  │
│ 一覧ページ監視  │ 一覧ページ監視    │ → URL特定         │             │
│                 │                   │ → カート投入      │             │
├─────────────────┼───────────────────┼───────────────────┼─────────────┤
│ PageRecorder    │ auto_login_       │ 受信側拡張        │ ❌ なし     │
│ (本拡張)        │ targettime        │                   │             │
└─────────────────┴───────────────────┴───────────────────┴─────────────┘
```

**本拡張の役割**: 一覧ページからの新商品URL抽出、保存、通知イベント生成

### 3.4 パターンI詳細

**シナリオ**: 複数のECサイトや商品URLを、定時に並行監視して在庫状態を検知したい。

```
┌─────────────────────────────────────────────────────────────────────┐
│ 情報収集                │ 購入準備          │ 購入実行          │ 購入確定    │
├─────────────────────────┼───────────────────┼───────────────────┼─────────────┤
│ 複数サイト定時監視      │ 時間帯前ログイン  │ 通知受信後の処理  │ 決済・確定  │
│ 在庫差分検知            │                   │ → カート投入など  │             │
│ 通知イベント生成        │                   │                   │             │
├─────────────────────────┼───────────────────┼───────────────────┼─────────────┤
│ PageRecorder (本拡張)   │ auto_login_       │ 受信側拡張        │ ❌ なし     │
│                         │ targettime        │                   │             │
└─────────────────────────┴───────────────────┴───────────────────┴─────────────┘
```

**本拡張の役割**: 複数サイト定時在庫監視、状態差分検知、通知イベント生成

### 3.5 非対応パターン

以下のパターンでは本拡張機能は使用しない。

| パターン | 理由 |
|---------|------|
| A | 事前情報あり + URL判明のため、パターン分析が不要 |
| B | Discord履歴分析が主となるため |
| E | 常時監視はSummaryMoniterが担当 |
| F | 再入荷監視はSummaryMoniterが担当 |
| G | ゲリラ販売はDiscord監視が主 |
| H | 定期パターンはDiscord履歴分析が主 |
| J | 抽選/予約は別フロー |

## 4. 責務境界

### 4.1 本拡張機能が担うこと

| 責務 | 詳細 |
|------|------|
| ページソース取得・保存 | HTML形式でダウンロード |
| スクリーンショット取得・保存 | PNG形式でキャプチャ |
| キーワード出現・消失検知 | 設定したキーワードの状態変化を検知 |
| 在庫状態差分検知 | 定時監視で在庫状態や新規URL差分を検知 |
| 通知イベント生成 | 検知結果を外部拡張向けメッセージに変換 |
| 監視間隔・期間のカスタマイズ | ユーザー設定に応じた調整 |
| 単一/複数URL監視 | モード切替による対応 |
| 監視設定のExcel入出力 | 設定の保存・復元 |

### 4.2 本拡張機能が担わないこと

| 非責務 | 担当 |
|--------|------|
| 通知先の最適化 | 受信側拡張 |
| Discord投稿監視 | discord_post_url_monitor |
| 自動ログイン | auto_login_targettime |
| 自動カート投入 | 受信側拡張 |
| 決済処理・注文確定 | 未対応（手動） |
| 受信後の購入実行判断 | 受信側拡張 |

## 5. 他拡張機能との関係

### 5.1 拡張機能一覧と役割分担

| 拡張機能 | 情報収集 | 購入準備 | 購入実行 | 購入確定 |
|---------|---------|---------|---------|---------|
| discord_channel_exporter | ✅ | - | - | - |
| **PageRecorder** | **✅** | **-** | **-** | **-** |
| SummaryMoniter | ✅ | - | ⚠️(検知のみ) | - |
| auto_login_targettime | - | ✅ | - | - |
| discord_post_url_monitor | ⚠️(Discord) | - | ✅ | - |

### 5.2 連携パターン

```
[本拡張機能]           [他拡張機能]
    │                      │
    ├─ ページ変化記録 ────→ discord_channel_exporter と併用
    │                      │   （過去データ分析）
    │                      │
    ├─ 在庫差分検知 ──────→ 受信側拡張へ通知
    │                      │   （通知先はメッセージ契約で分離）
    │                      │
    └─ パターン分析 ──────→ auto_login_targettime へ反映
                           │   （入荷時間帯の予測）
                           │
                           └─→ 受信側拡張が購入実行を判断
```

## 6. 出力データ形式

### 6.1 ダウンロードファイル

| 種別 | 形式 | 命名規則 |
|------|------|---------|
| ページソース | HTML | PageSource_YYYYMMDD_HHMMSS.html |
| スクリーンショット | PNG | Screenshot_YYYYMMDD_HHMMSS.png |
| 監視設定 | Excel | monitoring_config_export.xlsx |

### 6.2 保存データ（chrome.storage）

| キー | 内容 |
|------|------|
| monitoring_config | 監視設定（URL、セレクタ、キーワード等） |
| monitoring_state | 監視状態（実行中/停止等） |
| download_settings | ダウンロード設定 |
