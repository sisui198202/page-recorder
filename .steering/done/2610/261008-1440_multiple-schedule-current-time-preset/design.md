# Design: A/B 定時実行設定と現在時刻プリセット

## 実装方針

1. 単一URL A の予約は `single_keyword_schedule`（`enabled`、`startTime`）へ保存する。既存の単一URL B 用 `single_scheduled_watch` とは分離する。
2. background は A 専用の毎日アラームを同期し、保存済みの指定URLと既存の監視条件で開始する。開始済み A セッションがあればスキップし、設定は上書きしない。
3. 複数URL B のプリセットは対象追加・編集フォームだけを更新する。単一URL B と同じ時刻計算を再利用する。
4. 複数URL A の共通時間設定から今回追加したプリセットを取り除き、既存の毎日開始予約は維持する。
5. 単一URL B は予約ON/OFFで即時保存・再同期する既存の保存経路を使う。URL・商品取得セレクタが未設定なら background がアラームを作らず、状態表示で理由を返す。
6. 単一URL B の即時開始は、設定を保存後に専用メッセージで既存のBセッションを起動する。予約ONを要求せず、終了時刻は開始時刻から `immediateDurationMinutes`（既定3分）で算出する。停止はそのセッションだけを終了し、予約アラームを操作しない。

## UI と状態表示

- 単一URL A は予約ON/OFF、開始時刻、現在＋2分プリセット、予約状態を表示する。
- アクティブタブ選択中は A の予約操作を無効化し、指定URLへの切替を案内する。
- 複数URL B は開始・終了時刻の直後に開始＋2分・終了＋3分プリセットを置く。
- 単一URL B は A と同じ予約設定ブロック、使い方カード、状態表示の順にし、「予約だけで開始」「予約を止める」を表示する。
- 単一URL B の状態欄の近くに、3分を初期値とする即時監視時間、今すぐ開始、停止を置く。実行中は開始を無効化し、停止を有効化する。
- A は今すぐ監視・毎日開始予約で同じ相対的な継続時間を使うため、時間経過時の共通設定であることを表示する。B は「今すぐ監視」と「毎日開始予約」を分け、前者は継続時間、後者は開始・終了時刻を使う。
- 単一URL B の見出しは即時監視も含むため「検索結果・一覧ページ監視」とし、定時監視はその中の「毎日開始予約」として示す。
- 複数URL A は「今すぐ一括監視」「毎日一括開始予約」「時間経過時の監視継続時間（今すぐ・予約共通）」を区別して表示する。既存の共通設定・監視ロジックは維持する。
- 複数URL B は対象ごとの定時監視専用とし、即時監視の一括操作は追加しない。保存時に同日の開始時刻より後の終了時刻だけを受け付ける。
- 複数URL B の予約状態は、既存の `getScheduledWatchSitesStatus` 応答から `source: "popup-list-watch"` のみを抽出し、A と同じ状態カードで表示する。設定保存形式・アラーム同期経路は変更しない。
- 複数URL B の対象行には予約の有効・無効化ボタンを置く。`multiple_list_watch_configs[].enabled` を更新して保存後、既存の `resyncScheduledWatchSites` を呼び、次回アラームと状態カードを更新する。実行中セッションは既存の再同期処理どおり継続する。
- B の即時監視は、対象一覧のチェックで選択した保存済み対象だけを開始する。background は既存のサイト別セッションと tick 処理を使い、`trigger: "immediate"` と相対的な `windowEndMs` を持つセッションを作成する。予約無効の対象も開始できるが、定時実行中の対象は二重起動しない。
- 即時停止は `trigger: "immediate"` の B セッションだけを終了する。予約アラームおよび `trigger: "scheduled"` のセッションは操作しない。
- B のAI判断サポート設定は `multiple_list_watch_common_settings.downloadAiSupportFile` に保存する。Bセッション開始時にこの値と監視条件を `session.settings` に固定し、終了後に実行履歴を結合したMarkdownをダウンロードする。Aの `multiple_common_settings` とは共有しない。
- BのAI判断サポートはキーワード監視ではないため、設定表ではキーワード・初回キーワード検知を「対象外」、検知モードを「URL差分（新規商品URL）」と表示する。`window_end`と`new_product_detected`はBの正常終了として成功判定にする。
- B の即時セッションはログ上も `[immediate]` を使い、開始時は継続時間、終了時は「継続時間終了」または「手動停止」を出力する。定時セッションの `[schedule:n]`・「監視時間帯終了」は維持する。
- 複数URL A は開始元を `immediate` / `scheduled` として永続セッションに記録する。今すぐ一括停止は `immediate` セッションだけを停止し、予約の保存・解除は毎日開始アラームだけを操作する。予約開始セッションの手動停止は追加せず、共通 `duration` により終了する。
- 実行履歴の再描画前に各`details`の開閉状態を履歴キーで取得し、再描画後の同じ履歴へ復元する。初回だけ実行中の履歴を展開し、手動で閉じた状態も維持する。

## 検証方針

- UI 契約・時刻計算、A アラーム同期、指定URL起動、実行中スキップを unit テストで確認する。
- B即時監視の設定保存、予約OFFでの起動、指定時間での終了、二重開始防止、停止しても予約を維持することを unit テストで確認する。
- B のAI判断サポート設定の保存・セッション伝搬・終了時ダウンロード、および即時/定時ログ文言の分離を unit テストで確認する。
- 複数URL B の開始・終了時刻の順序検証と、複数URL A/Bの表示区分を unit テストで確認する。
- 複数URL A の即時停止が予約セッション・予約アラームを操作しないことを unit テストで確認する。
- 実行履歴を再描画しても、手動で開閉したチェック履歴の状態を維持することを unit テストで確認する。
- Chrome で単一URL A/B の予約ON/OFF・状態表示、A の保存・予約・起動、複数URL B の入力・保存、既存予約の回帰を手動確認する。
