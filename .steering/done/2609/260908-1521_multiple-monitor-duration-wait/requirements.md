# requirements — multiple-monitor-duration-wait

## 目的

複数URL監視のリロード後待機中に監視時間が満了した場合、待機完了後のキーワード判定・保存を実行せず監視を終了する。

## 背景

現在は監視処理の開始時だけ監視時間を確認するため、`reloadWaitAfterReload` が監視時間を超えると、待機解除後に本来終了済みの監視で判定・保存が実行される。

## 要件

- 待機開始前の既存の監視時間判定を維持する。
- 待機完了直後の状態を、満了・停止済み・継続可能の3状態に分類する。
- 満了時は既存と同じ終了処理を行い、停止済み時は何も実行せず終了する。
- 満了時は `checkKeywordChange` とダウンロード処理を呼ばない。
- `multiple` テストタブに、待機中の満了停止を再現する固定 2 URL シナリオを追加する。
- 当該シナリオは本番 `multiple_configs` と `multiple_common_settings` を変更せず、`multiple_test_scenario_state` のみを利用する。
- 当該シナリオでは手動DOM変更・自動再現を案内せず、待機完了後に満了していればキーワード判定・HTML・スクリーンショット保存を行わない。
- 通常の複数URL監視、既存 `multiple` シナリオ、系統B/C以外を変更しない。

## 受け入れ条件

- `duration < reloadWaitAfterReload` の場合、待機後に監視が終了する。
- 待機中に別実行が監視状態を削除した場合、待機解除後にログ・判定・保存を行わない。
- 監視時間が残っている場合、従来どおりキーワード判定へ進む。
- popup の専用シナリオで、5秒後のリロード・15秒の待機中に10秒の監視時間が満了することを確認できる。

## 起点

- `plan/todo.md` の「待機完了後の監視時間超過時の判定・保存抑止」
