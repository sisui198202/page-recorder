# requirements

## 目的

popup の監視導線を A/B/C に再整理し、B/C 定時監視を本運用へ影響させず短時間で確認できるようにする。Alfred `tes'` は実在サイト・実アラーム・必要時の通知を確認する補助フローとして拡張する。

## 背景

現在の A、B、C は popup と定時監視の責務が混在し、C 設定の運用状態や安全な検証手段が把握しにくい。ユーザー承認済みの実装計画「監視機能の再整理・定時テスト拡張・Alfred連携」を起点とする。

## 機能要件

- A のキーワード監視と B の単一サイト定時検証を popup 上で分離し、B は URL 必須の折りたたみ領域にする。
- C の設定元を JSON のままにして、popup ではサイト情報・状態・エラーの表示とアラーム再同期だけを提供する。
- C セクションでは、アラームを変更しない「C状態を更新」操作で、サイト一覧・直近実行結果・保存済み再同期結果を再取得できるようにする。
- popup を開いている間は、C 実行の有無にかかわらず5秒ごとに表示専用の C 状態を自動更新する。状態取得は重複させず、取得失敗時は前回表示を維持して警告ログだけを残し、popup メッセージを表示しない。
- C アラーム再同期後は、有効サイト数と実在する baseline・監視開始アラームの照合結果を popup に表示する。結果は `chrome.storage.session` に保持し、browser 起動中の popup 再オープン時に復元する。同期例外は失敗、有効サイトなし・実行に必要な設定不足・アラーム不足は要確認とする。
- C の実行結果は、指定時刻の開始、指定セレクタのテキスト取得、時間満了または新商品検知による終了まで追跡する。取得済みの時間満了・検知終了は正常完了、取得例外・未取得は失敗、テキスト未確認は要確認としてpopupへ表示する。popup は状態、実行時間、予定枠、終了理由、3件の取得数値、取得テキストのプレビューと全文展開を分離したカードで表示する。
- B/C のテストは最短開始で snapshot、tick、終了を確認し、本運用の状態や副作用を変更しない。
- B/C 安全テストの結果は、状態・対象・判定理由・商品取得セレクタ結果件数・snapshot取得件数・無副作用の範囲を分離したカードで表示する。
- テストタブでは、A系の single / multiple シナリオとB/C定時監視の安全テストを別タブにし、CをA系multipleのテストとして扱わない。
- A系 single の「開始直後に検知」は、専用タブ・一時DOM再現・検知・テスト専用ダウンロード・終了を自動判定する。進捗と結果はブラウザ起動中だけ session storage に保持し、popup 再オープン時に復元できる。完了時は通知許可、固定IDの通知作成、通知センター登録を確認して結果を保存する。ほかのA系シナリオは手動確認導線を維持し、通常監視・外部連携・baseline・single設定を変更しない。
- 本運用中の B/C 対象はテスト開始を拒否する。
- Alfred の正本スニペットと生成物で、C のバックアップ、絞り込み、時刻設定、同期、確認、復元を支援する。
