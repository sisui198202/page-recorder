# テストタブ計画書

## 概要

本書は、`PageRecorder` の popup に開発者向けの「テスト」タブを追加するかを整理する未着手の改善計画書である。  
目的は、既存の監視機能を壊さずに、手動テスト時の確認導線と操作準備を popup 内で集約し、検証の再現性と切り分け効率を上げることにある。

2026-08-27 時点では実装着手前の計画として扱い、詳細仕様や実装判断は後続の `.steering/` 起票で確定する。

**更新日**: 2026-08-27

---

## 1. 背景

- 現行 popup は `単一監視` / `複数監視` の2タブ構成で運用している
- 手動テスト時に確認したい情報や補助設定が複数箇所に分散している
- `tests/docs/` に正本の手順はあるが、popup から見た導線は整理されていない
- 通常利用向けの監視設定 UI に、開発・検証向けの補助導線を混在させ続けると責務が曖昧になる

---

## 2. この計画で扱う対象

- popup 内の新規 `テスト` タブ追加方針
- 開発者限定で使う手動テスト支援 UI の整理
- 既存の手動テスト導線を popup から辿りやすくするための表示項目設計
- `単一監視` / `複数監視` タブとの責務分離

扱わないもの:

- 一般ユーザー向け正式機能としての公開設計
- background の大規模な制御変更
- storage schema の変更
- external messaging payload の変更
- ダミーデータ投入、強制状態変更、破壊的リセット操作

---

## 3. 想定する役割

`テスト` タブは、通常の監視設定を置き換えるためのタブではなく、開発・検証時の補助導線として扱う。

想定する役割:

- 手動テスト開始前に確認すべき前提の集約
- 現在の監視モードや状態確認への導線提示
- `tests/docs/` の正本手順へ進む前の入口整理
- 既存 UI に点在するテスト補助項目の整理先

想定しない役割:

- 日常運用の主要操作画面
- 既存監視開始・停止の主導線
- 内部状態の直接編集画面

---

## 4. UI 方針

### 4.1 基本方針

- popup の既存タブ群に `テスト` を追加する
- 対象ユーザーは開発者・検証者に限定する
- 一般利用向け設定よりも、確認しやすさと切り分けしやすさを優先する
- まずは「情報集約」と「導線整理」を主目的とし、操作系は最小限に留める

### 4.2 画面に含めたい内容

- テスト前の共通前提チェック
- 監視モード別の確認ポイント
- Service Worker Console や関連手順への導線
- `tests/docs/README.md` を起点にした手順案内
- 必要なら既存の手動テスト補助設定の移設候補整理

### 4.3 画面に含めない内容

- 通常ユーザー向けの監視設定編集の全面移動
- 保存データの直接書き換え
- 本番運用で誤操作につながる強制実行機能

---

## 5. 既存 UI との境界

### 5.1 `単一監視` / `複数監視` との関係

- `単一監視` と `複数監視` は従来どおり監視設定と実行の主導線として残す
- `テスト` タブは補助導線として追加し、既存フローの責務を奪わない
- 既存タブにあるテスト向け項目は、重複や責務混線がある場合に限って整理対象とする

### 5.2 文書との関係

- 手動テスト手順の正本は引き続き `tests/docs/` とする
- `テスト` タブは正本の代替ではなく、入口と確認支援に限定する
- 詳細手順、復旧方法、長文トラブルシュートは popup へ過剰に持ち込まない

---

## 6. 想定効果

- 手動テスト開始前の迷いを減らせる
- どの文書から読むべきか判断しやすくなる
- 開発者向け補助情報を通常設定 UI から分離できる
- `PageRecorder検知改善取込` のような監視挙動確認タスクでも、確認導線を共通化しやすくなる

---

## 7. 実装時の論点

- `テスト` タブを常時表示にするか、開発時のみ表示にするか
- 既存の手動テスト補助設定を現位置に残すか、`テスト` タブへ寄せるか
- popup だけで完結させる情報と、`tests/docs/` へ委譲する情報の境界
- 監視状態表示をどこまで載せるか

---

## 8. 次の接続先

- 実装する場合は `.steering/` に requirements / design / tasks を起票する
- requirements では対象ユーザー、表示条件、責務境界を先に固定する
- design では popup のタブ構成、表示項目、既存 UI からの移設有無を整理する
- tasks では UI 追加、既存テスト補助項目の整理、手動確認導線の更新を Phase 単位で分解する

---

## 9. 完了条件

- `テスト` タブの役割が通常監視 UI と明確に分離されている
- 開発者向け手動テスト支援としての目的が文書化されている
- `tests/docs/` を正本にしたまま、popup 上の入口改善方針が整理されている
- 後続の `.steering/` に落とせる論点が明示されている
