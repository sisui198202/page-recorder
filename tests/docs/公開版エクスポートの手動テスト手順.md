# 公開版エクスポートの手動テスト手順

> 🔍 `scripts/export-public.sh` で書き出した公開版に、個人環境の情報が残らず、テストと拡張機能の読み込みが通ることを確認する。

## 概要

GitHub 公開用のコピーを書き出すスクリプトの確認手順。公開前に毎回この手順で確認する。

- 対象: `scripts/export-public.sh`、公開版（既定 `~/Work/Projects/PageRecorder-public`）
- 前提: PageRecorder リポジトリのルートで作業する。Node.js・npm・Chrome がある

## 基本的な使い方

### 手順1: 誤上書き防止の確認

目的:
- 目印ファイルの無い既存フォルダを書き出し先に指定したとき、何も書き換えずに止まることを確認する（別のフォルダを壊さないため）

実行:

```bash
cd ~/Work/chromeExtensions/PageRecorder
mkdir -p /tmp/pr-guard && echo keep > /tmp/pr-guard/important.txt
bash scripts/export-public.sh /tmp/pr-guard; echo "exit=$?"
ls /tmp/pr-guard
```

期待結果:
- `❌ 書き出し先が空ではなく、目印ファイル .pagerecorder-public もありません` と表示され、`exit=1`
- `/tmp/pr-guard` には `important.txt` だけが残っている

### 手順2: 公開版の書き出しと公開前チェック

目的:
- 公開版を書き出し、ローカルパス・クライアントID・個人メール・Webhook・秘密情報ファイルが残っていないことを確認する

実行:

```bash
cd ~/Work/chromeExtensions/PageRecorder
bash scripts/export-public.sh
```

期待結果:
- 公開前チェックの5項目がすべて `0 件`
- `✅ 書き出し完了: N ファイル` と表示され、終了コードが 0

### 手順3: 置換と除外の確認

目的:
- クライアントIDの置換、購入フロー系資料と PDF の除外、README・LICENSE の差し替えを確認する

実行:

```bash
cd ~/Work/Projects/PageRecorder-public
grep '"client_id"' manifest.json
ls 参考 2>&1; find . -name '*.pdf' -not -path './node_modules/*' | wc -l
head -3 README.md; head -3 LICENSE
```

期待結果:
- `"client_id": "YOUR_CLIENT_ID.apps.googleusercontent.com"` と表示される
- `参考` は存在せず、PDF は `0`
- README の1行目が `# PageRecorder`、LICENSE の1行目が `MIT License`

### 手順4: 公開版のテスト

目的:
- 公開版だけで依存関係を入れてテストが通ることを確認する（`jest-chrome` の peer dependency が古い Jest を指定しているため `--legacy-peer-deps` が必要）

実行:

```bash
cd ~/Work/Projects/PageRecorder-public
npm ci --legacy-peer-deps
npm test
```

期待結果:
- すべてのテストスイートが成功する（作者環境のファイルを読むテストは、そのファイルが無ければ skipped になる）

### 手順5: 非公開リポジトリに副作用が無いことの確認

目的:
- スクリプトが非公開リポジトリのファイルを書き換えていないことを確認する

実行:

```bash
cd ~/Work/chromeExtensions/PageRecorder
git status --short
```

期待結果:
- スクリプト実行前と同じ差分だけが表示される（実行によって増えた変更が無い）

### 手順6: 拡張機能としての読み込み

目的:
- クライアントIDをプレースホルダーにした公開版でも、拡張機能として読み込めることを確認する

実行:
1. Chrome で `chrome://extensions` を開き、デベロッパーモードをオンにする
2. 「パッケージ化されていない拡張機能を読み込む」で `~/Work/Projects/PageRecorder-public` を選ぶ
3. 拡張機能のアイコンから popup を開く
4. 確認後、読み込んだ公開版は削除する（非公開版と同時に有効にしない）

期待結果:
- エラー表示なしで読み込まれる
- popup が開き、監視設定の画面が表示される

## 判定・保証範囲

| 項目 | 内容 |
|------|------|
| 成功条件 | 手順1〜6の期待結果をすべて満たす |
| 成功時の保証範囲 | 確認した時点の公開版に、検査対象の5種類の情報が残っておらず、テストと読み込みが通ること |
| 失敗境界 | 公開前チェックで1件でも見つかる、テストが失敗する、読み込みでエラーが出る |
| 失敗時に保証されないこと | 公開版の安全性。見つかった項目を直して手順2からやり直す |
| 保証しないこと | 検査パターンに当てはまらない個人情報（例: 文中の氏名・住所）が無いこと。Gmail 通知の動作（公開版にはクライアントIDが無い） |

## ポイント

- 公開前チェックは、ファイル名と件数だけを表示する。秘密情報の値は表示しない
- 書き出しは毎回作り直す。公開版で直接ファイルを編集しない（次の書き出しで消える）

## まとめ

- 書き出し → 公開前チェック0件 → テスト → 読み込み確認、の順で確認する
- 非公開リポジトリは変更されない
