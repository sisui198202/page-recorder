# 在庫監視 設定ガイド

## 概要

PageRecorder の在庫監視機能には、**2つの監視モード** があります。
それぞれで「商品URLを開く」設定の参照先が異なります。

---

## 監視モードの違い

| 項目 | SingleSite監視 | MultiSite監視 |
|------|---------------|---------------|
| 開始方法 | popup から手動開始 | JSON設定で自動開始 |
| 設定ファイル | popup設定（chrome.storage） | scheduled-watch-sites.json |
| 用途 | テスト・一時的な監視 | 本番運用 |
| 複数サイト | 1サイトのみ | 複数サイト対応 |

---

## 待機時間の意味整理

監視まわりの「待機」には、役割の違う概念が混在します。現行実装を読むと、少なくとも次の3種類を分けて扱う必要があります。

### 1. DOM準備完了待ち

- `tab.status` や `document.readyState === "complete"` を確認し、必要に応じて監視対象DOMの出現まで待つ処理
- これは通常運用で毎回必要になりうる基本待機です
- `PageRecorder` では `waitForPageReady()` がこの役割を担います

### 2. 初回基準化のための待機

- これは「監視開始直後に、現在状態をすぐ判定せず、最初の基準をどう作るか」という話です
- `AutoCartAgent` 側で使う `reloadWaitAfterReload` は、毎回の周期待機ではなく、単一サイト監視かつ `initialDetection=false` のときに初回基準化を安定させるための待機として整理します
- 現行の `PageRecorder` には、この意味の専用設定はありません

### 3. リロード後の追加待機

- `PageRecorder` の `reloadWaitAfterReload` は、DOM準備完了待ちの後に追加で止める待機です
- 主用途は、手動テスト中に DevTools で要素を書き換える時間を確保することです
- 通常のページ読み込み完了判定そのものを置き換える設定ではありません

### 動的ページの考え方

- 「静的ページか動的ページか」を固定分類で決めるより、`readyState=complete` 後も監視対象要素が遅れて出現・差し替えされるかで判断します
- 実運用では、サイト設定で待機要否を明示する方式を基本にし、実行時の `pending` や selector 未出現は補助材料として扱うのが安全です
- `dynamicContent` のような情報があっても、現時点では毎回待機へ自動切替する確定フラグとしては扱いません

### 将来の実装候補

- 将来的には、`AutoCartAgent` に「各周期のリロード後待機」を初回基準化用待機とは別設定で持たせる余地があります
- ただし、これは 2026-08-28 時点では未実装です

## 「商品URLを開く」設定

### SingleSite監視（popup開始）

**設定場所**: popup の「増加検知時に商品URLを開く」チェックボックス

```
popup → 「増加検知時に商品URLを開く」
```

### MultiSite監視（JSON設定）

**設定場所**: `src/config/scheduled-watch-sites.json`

```json
{
  "notification": {
    "openProductUrl": true
  }
}
```

---

## よくある問題: 検知時に商品URLが2つ開く

### 原因

以下の両方でURLを開く設定になっている:

1. PageRecorder の JSON設定 `openProductUrl: true`
2. discord_post_url_monitor が通知を受けてURLを開く

### 解決策

どちらか一方の設定をオフにする:

**オプションA**: PageRecorder側をオフ
```json
// scheduled-watch-sites.json
"notification": {
  "openProductUrl": false
}
```

**オプションB**: discord_post_url_monitor側をオフ
- その拡張の設定でURLを開く機能をオフにする

---

## 設計の理由

### なぜ設定が2つあるか

- **SingleSite監視**: JSONにないサイトの定時差分検知テストに使用
- **MultiSite監視**: 本番運用で使用

テスト用途ではpopup設定が便利で、本番運用ではJSON設定で一括管理が効率的です。

### 両者は独立

- popup設定を変更しても、MultiSite監視には影響しない
- JSON設定を変更しても、SingleSite監視には影響しない

---

## 推奨運用

1. **テスト時**: popup設定を使用（SingleSite監視）
2. **本番運用**: JSON設定を使用（MultiSite監視）
3. **2つ開く場合**: どちらか一方をオフにする
